## 二、逐项清单

### A. 姓名判定层（R4 评分层 / surname_pool）

**D2. 姓氏表补缺（付/肖/闫/覃）+ 同音易混词守卫**
- 上游现状：R4 评分层与 `looks_like_person_name` 均以**百家姓**为姓氏来源，缺现代简化姓/生僻姓。
- 缺陷实证：「计划财务部**付松龄**总」被判非姓名漏脱（付＝傅的简写，百家姓只有"傅"）；同类 肖＝萧、闫＝阎；覃（华南常见）亦缺。
- 本地方案：`_SURNAMES |= set("付肖闫覃")`，并配套 `_SURNAME_HOMONYM_STOP`（支付/付款/付息/付费/肖像/时候/等候/候选/涂料/代表/蓝色/红色…）并入姓名判定，抵消子串冲突。
- **建议上游做成配置**：`extra_surnames` / `surname_homonym_stop`，便于各接入行按本地姓氏分布扩充。
- 实测：HTB s41 图 `计划财务部付松龄总` → 打码。

**D3. 行业/技术语义词守卫（`_DOMAIN_WORD_STOP`）**
- 上游现状：`looks_like_person_name` 以"首字在姓氏表"为放行条件——凡首字恰为姓氏的**行业词**都会被误判人名。
- 缺陷实证（HTB 架构图/图标 OCR 单元格，被整格打码）：`金融`（金）、`安全运维`/`安全层`（安）、`公务卡`（公）、`通用记账`（通）、`文件`（文）、`包手机`（包）、`金额`（金）、`应用层`（应）。
- 本地方案：新增语义词表（业务域/技术域/办公域，约 90 词），**含任一子串即一律不判为人名**。挂载点：`looks_like_person_name` 与 `_LONE_NAME_RE` 兜底分支。
- 价值：这是评分层**结构性的假阳性来源**（金/安/公/通/文/包 全部在百家姓内），建议优先采纳。
- 实测：架构图 `金融/安全运维/应用层/安全层/公务卡/通用记账/金额/文件/包手机` 全部恢复可读，run9→run10 文本节点回退 0 处。

**D17. 语义词守卫扩充（假阳性收敛）——三组**
- 上游现状：`_DOMAIN_WORD_STOP` + 表格口径 `_CELL_NONNAME_WORDS` 是主要假阳性拦截层，但词表随场景增长。
- 本轮新增（判据：含任一子串即不判为人名/不打码）：
  1. **测试域**：`功能/界面/白盒/黑盒/灰盒`——`全功能、全界面测试`、`测试厂商白盒、黑盒测试` 因首字落百家姓（全/白）被判名；
  2. **通用业务域**：`产品/业务/错误`——`全产品、全业务路径` 被顿号名单规则吞成 `XXX、XXX径`；`指定责任人时错误` 被角色槽位规则吞成 `指定责任人XXX`（`时` 是百家姓）；
  3. **角色方称**：`行方/甲方/乙方/双方/各方/责任方/承建方/建设方/业主方/相关方/公司方/厂商方/业务方/实施方/需求方`——表格"责任人"列取值 `行方` 被"生僻姓 2 字兜底"打码。
- 另一处**业务分类守卫**：`_generic_bank_pass` 中 `…类银行 / …型银行 / …种银行 / …等银行` 不是行名——`核准类银行结算账户电子化` 曾被吞成 `XX银行结算账户电子化`。
- 建议：`_DOMAIN_WORD_STOP` 与 `_CELL_NONNAME_WORDS` 合并为单一"非姓名语义词表 + 词根匹配"配置项；**2 字兜底**建议加"首字须 ∈ 姓氏表"闸门（实测 `行方/甲方/乙方` 均被该兜底误伤，而真名 2 字首字基本必为姓）。

**H2. 生僻姓「后」的动宾短语守卫**
- 现象：`功能稳定后启动`→`稳定XXX`、`批准/审核后方可`→`批准XXX`（农芯 s28/46/50）。
- 根因：「后」∈百家姓，`后X` 被角色裸槽位/姓名头规则当人名。
- 方案：`_SURNAME_HOMONYM_STOP` 追加 后方/后启/后续/后将/后即/后由/后再/后进（两脚本同口径；与既有 支付/肖像/候选 系列同表）。

**E3. 角色槽位后的动词/程度词守卫（`_NONNAME_WORDS` 扩充）**
- 现象：正文 `测试人员应掌握…` → `测试人员XXX`；误伤走"角色槽位 + `looks_like_person_name("应掌握")`"支路（`应`∈百家姓，`掌握` 不在守卫表）。
- 方案：`_NONNAME_WORDS` 追加 43 个"角色槽位后常见动词/程度词"：
  `掌握/熟悉/了解/具备/能够/可以/需要/遵守/执行/参加/参与/按照/根据/及时/按时/认真/严格/准确/清晰/完整/正确/合理/有效/主动/积极/持续/协调/推动/配合/安排/组织/指定/确认/同意/汇报/分工`
- 复用建议：R4 评分层若已有语义词表直接并入；这批词共性是"**跟在角色/岗位词后面**"，不是独立词表。

### B. 表格列脱敏（C9 + N-A）

**D6. 表头驱动列脱敏的"列名"判定收紧**
- 缺陷实证（HTB s24/s30）：① `测试人员风险` 这类**数据单元格**被当列名 → "问题与风险类别"列被整列逐格打码，误伤 `合计/士气风险/极度疲劳`；② `前六大厂商目前人员投入情况`、`总行部室当前常驻项目组人员情况` 等**跨列合并标题行**使厂商列被当姓名列。
- 本地方案：① 跳过**非空单元格 < 2** 的合并标题行；② 列名须 ≤ **20** 字、无句读、不以"风险/问题/类别/情况/原因/影响/措施/内容/分析"收尾。
- **回归坑（务必保留测试）**：阈值一度设为 8 字，把 `UAT测试牵头人/负责人`（13 字）挡在门外，致 4 张 UAT 表姓名列**整体漏脱**——阈值定 20，改动此处必须回归该列名。

**D7. 单元格姓名宽松口径的语义 / 厂商守卫**
- 本地"生僻姓兜底"（2–4 字单元格逐段判定）会把语义词与厂商名一并吞掉。
- 方案：`_CELL_NONNAME_WORDS`（风险/合计/士气/疲劳/科技/厂商/人员…）作语义词守卫；`_VENDOR_PREFIX` 作厂商名前缀守卫（**厂商名按用户口径不脱敏**）。

**D15. 表头驱动列脱敏：表头行识别 + 列表头关键词 + 姓名列取值预扫**
- 上游现状（C9）：取表格**前两行并集**作为表头判定列名。
- 缺陷实证：QRCB 章程 s19 表一，第 2 行是**数据行** `组长｜赵维`，其"组长"被当第二表头 → ①列号被污染（**角色列被整列打码**）；②首行数据被排除在数据区外（`赵维` **漏脱**）。
- 本地方案三点：
  1. `_tbl_name_cols(rows)`：**逐行判表头，某行给出列名即认定为表头并 break**（不再并集）；
  2. `_TBL_NAME_HEADER_KW` 增补 `管理组`（"测试管理组"列原不含姓名类关键词，整列 7 人漏脱）；
  3. 新增 `_collect_table_name_values()` **预扫表格姓名列取值 → 注入 `_EXTRA_NAMES`，做全文同名替换**（正文引用 `王根利的B角` 不在表格列内，仅靠列脱敏够不着）。
- 建议：把"预扫取值 → 全文替换"做成上游通用能力——**表头驱动的列脱敏 + 同文档全文联动是两件事**，上游目前只有前者。
- 实测：QRCB 章程 s19 表一 `赵维`→`XXX`、表二「测试管理组」列 7 人全部 `XXX`、正文 `王根利的B角`→`XXX的B角`。

**E1. 单元格「整格成句即跳过」（`_CELL_PROSE_RE`）**
- 现象：《章程》第 3 页 `参加晨会，获取当天工作安排。`→`XXX，获取当天工作安排。`；`安排明日工作计划、分工、注意事项`→`…、XXX、…`；第 5 页 `实时，关注"阻塞缺陷"，及时协调、上报`→`XXX，…，XXX、XXX`。
- 根因链：表头 `测试组长 / 测试人员 / 测试执行人员` 命中姓名类关键词 → `_tbl_name_cols` 把**角色列**判成**姓名列** → 整段工作说明逐格进 `mask_cell_names` → `_CELL_SPLIT_RE([、/，,；;\s]+)` 按标点切成 2–4 字碎片 → 生僻姓兜底照单全收。
- 方案：`mask_cell_names()` **顶部**先判"整格是否成句"——格内出现 `，。；！？` 任一 → 直接原样返回。
  ```python
  _CELL_PROSE_RE = re.compile(r"[，。；！？]")
  if _CELL_PROSE_RE.search(txt):
      return txt
  ```
- 边界依据：真实姓名格只会用 `、` / `/` 分隔（`赵辉、赵维`），**姓名格不会写中文句读**。
- 效果：《章程》第 3/5 页误伤 **17 处全部恢复**，同批真姓名 `母洪康/敬潇潇/阳宇/南国强/候非/衣稳/赵辉/赵维` 零漏脱。

**E2. 表头驱动列脱敏：禁止用"成句占比"做整列剔除**
- 反例实测：曾把列判据改成"数据区成句格占比 > 1/3 就剔掉整列" → docx《总体方案》**「审核人」列** 7 格里有 3 格是 `根据讨论内容修订` 之类说明 → 整列被剔 → `赵辉/赵维` **整条漏脱**。
- 结论：列级判据只保留**表头识别**；"这一格是不是姓名"必须在**格级**判定（即 E1）。列判对 + 格判对，两层各管一段，不要在中间再插统计剁刀。
- 建议：直接写进上游 C9 注释，避免后人重复踩坑。

**H3. 表头设备/品牌词排除表（"设备厂商"列的"联想"误伤）**
- 现象：农芯 s44 设备借用表，`设备厂商` 列的 `联想` 整列被打码。
- 根因：表头姓名关键词含裸「厂商」→ `设备厂商` 被判姓名列。
- 方案：新增 `_TBL_HDR_NONNAME` 排除表（设备厂商/硬件厂商/产品厂商/设备品牌/设备型号/设备类型/设备名称/设备用途），表头判定先行排除。⚠ **勿放裸"设备"**——会误伤"设备负责人"这类真姓名列。

### C. 角色槽位与名单（C10 + N-B）

**D8. 无冒号角色槽位的连词守卫**
- 缺陷实证：`标准不降，测试厂商和开发厂商保证资源` 中，"厂商" + 后续"和开"（其后接"发"）被判为姓名 → 误打码。
- 方案：`_NAME_LEAD_STOP`（和/与/及/并/或/且… 开头）直接放弃；并加"段 + 后一字含非人名词（开发/实施…）"即放弃。

**D11. 名单续行（`_NAME_HEAD_LIST_RE` + `_PERSON_TAIL_HINT`）**
- 缺陷实证：组员名单跨行续排，行首是姓名、其后接说明文字（`梁红兵、各系统行方项目经理、实施厂商项目经理`），既非纯名单行也无角色前缀 → 漏脱。
- 方案：行首姓名列表 + **后半段须含人事语义词**（项目经理/厂商/实施/组员/成员/负责人…）门槛 —— 防 `核心、外围` 这类普通并列被误伤。
- 实测：`梁红兵、各系统行方项目经理…` → `XXX、各系统行方项目经理…`。

**D16. 顿号姓名名单规则：挂载 + 执行顺序 + 残字虚词守卫**
- 上游现状：`_NAME_LINE_RE`、`_NAME_HEAD_LIST_RE` 都在，但**"任意前缀 + `：` + 顿号名单"**（如 `工具支持：窦磊、王富生`）无人处理。
- 本地方案：
  1. `_LIST_NAME_RE = (前缀[\u4e00-\u9fa5A-Za-z]{2,12})\s*[:：]\s*(名单)`，`_list_repl` 要求**全部段落均判为人名且 ≥2 个**（避免"全产品、全业务路径"式并列短语被吞）；
  2. **顺序陷阱**：必须排在确认名单/`_EXTRA_NAMES` **字典替换之前**；
  3. **残字清理虚词守卫**：`XXX[\u4e00-\u9fa5]{1,2}` 会把 `王根利的B角` 吃成 `XXXB角` → 改为 `XXX(?:(?!虚词)[汉字]){1,2}`，虚词集 `_RESIDUE_STOP = 的了和与及或等是在中上下将把被由从向对为以并而同则着过们`。
- 实测：QRCB 章程 s19/s20 三处补齐；回归 JRCB/HTB/柳州 0 外溢。

**H1. 名单规则必须排在"短标签槽位"之前，且替换必须保留「标签＋冒号」**
- 现象：`工具支持：窦磊、王富生` 输出成 `工具支持XXX、王富生`——**冒号丢失**且第二人漏脱。
- 根因链（两条叠加）：①新加的短标签槽位规则 `标签：姓名` 先命中 `工具支持：窦磊`，返回 `label+替换名` 时把 `：` 丢了；②"窦磊"先变 XXX 后，顿号名单规则再也匹配不到 `王富生`。
- 方案：① **顺序**：`标签[：:]\s*姓名(、姓名)+`（名单形态）必须先于 `标签[：:]姓名`（单名槽位）；② **替换保形**：槽位类替换一律保留原 `标签＋冒号`，只替换姓名段。
- 效果：QRCB 章程 s20 复原为 `工具支持：XXX、XXX`；桂林 s25 四个短标签姓名照常生效。

### D. 银行名判定链（R3 / C4）

**D4. 行品牌词脱敏（`_BANK_BRAND_RE`，内嵌于系统名/产品名）**
- 上游现状：R3/C4 只处理 `…银行` **整名形态**，品牌词内嵌在业务系统名/产品名时整体漏脱或误保留。
- 本地口径（用户决议）：**品牌词是行标识，即使内嵌于业务系统名也须脱敏** —— `红塔云按揭系统` → `XX云按揭系统`。
- 方案：`BANK_BRAND_WORDS = ("云南红塔", "红塔", "富滇")` + `_BANK_BRAND_RE = (品牌词)(?!银行)`：**只替换品牌词本身、保留其后成分**；负向断言跳过整名形态（`云南红塔银行`/`红塔银行`/`富滇银行` 仍由通用银行名兜底统一打成 `XX银行`）。
- **顺序陷阱**：本规则必须排在通用银行名兜底**之后**；否则 `云南红塔银行` 会变成 `云南XX银行`。图片侧 `_IMG_KEYWORDS` 同步并入品牌词。

**D9. 银行名兜底的「前导词剥离」（`_BANK_LEAD_STOP`）**
- 缺陷实证：`稳定性等指标是否满足红塔银行未来5-10年…` → 贪婪 `[汉字]{2,6}银行` 把 `是否满足红塔银行` 整体吞成 `XX银行`，**正文"是否满足"丢失**。
- 方案：先剥离句法前导词（是否/满足/针对/依托/… ）再替换，输出 `是否满足XX银行`。

**D10. 机构泛称收尾守卫**
- 缺陷实证：`业务条线及分支行` 被整段吞成 `XX支行`；`项目组当前全职驻场参与的总分行业务人员` 丢掉"驻场参与的"；`各分支行…` 变 `XX支行`。
- 方案：前缀以"分/总"收尾视为**泛称**保留；`总行` 加入泛称表 `_GENERIC_ORG_PREFIX`；前缀尾部 `等/及/和` 不吞（`…等分行` 的"等"须保留）。
- 实测：`业务条线及分支行` 原样保留。

**D13. 业务系统名 / 业态词保留表扩充**
- `_KEEP_RE` 增补业态词 `个人`：`个人银行账户报送系统` 不再被脱成 `XX银行账户报送系统`；
- 与第 1 批 C4 的业态词表（微信/视频/远程/电话/手机/网上/直销/数字/智慧/云… + 银行）合并维护。
- 注：与 D4 的边界——**业态词保留**（个人银行账户报送系统），但**行品牌词脱敏**（红塔云按揭系统 → XX云按揭系统）；两者可同时存在于一个系统名中，需按"先银行兜底 → 再品牌词"顺序执行。

### F. 图片 OCR（C11）

**D1. 图片 OCR「行内姓名区间」打码（`_ocr_name_spans`）**
- 上游现状：C11 的 `_classify_line` 把一行判为姓名就对**整行**打码；正文式行（一句话里嵌姓名）无法处理，只能整行糊或漏脱。
- 本地方案：新增按**字符区间**定位的 `_ocr_name_spans(txt)`，返回需打码的 `[(s,e)]`，按"区间/行长"比例切子矩形，**只糊姓名、保留正文**。含 5 类模式：
  1. **前缀 + "：" + 名单**——前缀放宽到 角色词 / 部门·机构（…部/室/组/中心/公司）/ 厂商简称；用 `finditer` 取**最后一个有效前缀**（应付 OCR 多级前缀 `优秀个人（9月）：信息科技部：王云、吕双双；`）。
  2. **角色词 + 姓名**——`技术总体组组长谢红、副组长叶鹏等参加`；尾部连接/敬称字裁切（`叶鹏等`→`叶鹏`）。
  3. **姓名 + "总"（敬称）**——`谢红总和康皓总参加`；以"总"为锚**回看 2/3 字窗口逐个试**，且"总"后须接非中文或连接/动词字（防 `成长总结`/`总体组`）。
  4. **单姓 + "行"**——`邓行`＝邓行长简写。
  5. **名单首项**——OCR 把"组长"截成两个字块时（`长谢红、副组长叶鹏`），首项失去角色前缀；仅当整行另含角色词时启用。
- 另：`_ROLE_PREFIX_RE` 由 `^…$` 全行锚定 + `match` 改 `search`（OCR 常把前缀噪声并进同一行，如 `且 (组长：普新洋)`），并返回**姓名起始下标**。
- 实证：HTB 61 页 pptx 中 s13/s22/s23 评优名单图、简报图，共 20 张图命中、区间打码 60+ 处。

**D12. OCR 单元格判定的两个口径**
- `_NAME_LIST_RE` 分隔符补 `/`、`／` 与尾随分隔（OCR 会把 `刘殿麒、马杰` 截成 `刘殿麒/马`）；
- **单字段不参与判定但须至少 1 段实姓名**（避免 OCR 截断碎片被判/漏）；
- 生僻姓兜底 `_OCR_RARE_SURNAMES`（百家姓外的真实姓氏，如"呼晓栋"）——建议上游做成可配置项。

**E7. 图片 OCR 年份选区打码（`rects_year`）**
- 现象：《总体方案》图5-1-1（里程碑计划截图）上 14 处 `2025.x.x` 的年份原样可见；正文侧早有"仅年份 YYYY"（D14），图片侧无对应实现。
- 方案：OCR 行内 `20[12]\d` 命中段 → 按字符占比折算像素区间 → 马赛克**只打年份段，月日保留**（`2025.3.31 → ████.3.31`）。
- 实证：原图 OCR 出 14 条年份行，规则打码 14 处，输出图 OCR 年份行 0 条。
- ⚠ **环境前提**：`rapidocr` 未安装时整个 OCR 选区打码**静默关闭**。上游引用本规则时建议把"OCR 不可用"升级为**显式告警/人工检查项**，不要静默跳过。
- 无 OCR 兜底（本轮交付现场）：红色文字标签按"像素聚类 → 列投影切数字组"分组，≥3 组（`2025.3.31` 型）即年份标签打第一组，2 组（`10.31` 型）不动；与 OCR 交叉验证 14/14 一致。

**G2. 架构图密排小字表格不能依赖 OCR 行框**
- OCR 框在密排小字上斜跨两行/漏检续行。改为「标签行锚定 + 表格框线定位」整格遮蔽标签以下内容（OCR 漏检者同样覆盖）；标签实际墨迹底 = 从标签框顶起第一段连续墨迹（空隙≤1 行）的末端（OCR 框常把下方姓名顶部套进框，用框底会留残条）。
- **墨迹剖面 x 只能用标签框自身范围**——用整格 x 会把边框连续墨迹算进剖面，空隙行永有墨，判不出间隙致矩形退化整格漏打。
- 实测：柳州 image3 组织架构图重打码（对公存款组/公共业务组等 14 格）。

**H5. 组织架构图「角色卡＋底部小组表」整图口径沉淀 ＋ 场景门槛设计**
- 背景：柳州 4.3 组织架构图（`word/media/image3.png`）的"框线定位整格遮蔽"修复（G2）原本是一次性脚本＋外科回补，整份重跑即被冲掉。
- 方案（沉淀为 `process_image` 内前置场景通道 `_redact_orgchart_table`）：
  - 上半部：角色前缀行保留前缀、冒号图像定位后打码；纯姓名行整行打码；打码矩形先对"保留行"收缩；
  - 底部：`××组：`标签行锚定 + 表格框线定位，**整格遮蔽标签行以下全部内容**；
  - 强马赛克（块高=行高，8px 弱马赛克仍可辨字形）；
  - **场景门槛**：底部**带冒号**组标签 ≥3 且 角色前缀行 ≥2 且存在表格框线；命中→本通道取代通用通道（保证与人工返工结果**逐字节一致**），未命中→通用通道（行为与旧版全同）。
- **关键教训（门槛设计）**：第一版门槛用"行尾为『组』**或**冒号"计数 → 广西农商组织架构图（框标题以"组"结尾、**无冒号**）被误命中，且因专用通道未复刻通用通道的名单多数决/已知名守卫而**反向泄漏**人名＋银行 logo。修正为**只数带冒号标签**（柳州 13 个 / 广西农商 0 个）。但**遮蔽选择**仍用宽条件——OCR 会把 `中间业务组：` 的冒号丢掉，宽条件才能兜住、保持字节一致。
- 通用经验：**把某张图的专用口径沉淀成"场景通道"时，要么在通道内补齐通用兜底（银行名/known_names/名单多数决），要么把门槛收窄到只有目标场景命中——至少做其一，并在全量语料上回归。**

**H6. 图片 OCR 选区打码必须"复验迭代"（打码改变 OCR 输入）**
- 现象：HTB 进展表截图（image32/34）打码后复验 OCR 仍读出 `史超`/`马骥`。定位发现：马赛克矩形**没有打错位置**——`马骥` 在图上共 5 处，首轮 OCR 只检出 3 处并已正确打码；**打码改变图像上下文后，OCR 在首轮漏检的密排单元格上新检出**剩余 2 处。
- 根因：单轮 OCR 的召回缺口是结构性的——密排小字表格里 OCR 框斜跨两行/漏检，检出与否依赖周边上下文；打码必然改变上下文。
- 方案：打码后**重跑 OCR**，对新检出的敏感行继续走同一套分类/打码，直至无新增（≤3 轮收敛）。两脚本同口径（ppt `_ocr_region_mask` / docx `process_image`）；轮次 ≥2 时孤字探测/冒号定位改用**最新图像像素**。
- 效果：HTB image32/34 复验残留清零；全量重跑增量**恰好 4 张图片部件**（image31/32/34/35，其中 2 张真修复、2 张马赛克重相位），其余全部件逐字节不变。

### G. EMF / WMF 矢量图（C1）

**E4. WMF/EMF 文本记录解析 + 跨记录片段配对（图标内文本漏脱）**
- 现象：第 10 页 OLE 附件图标里，文件名用 WMF 文本记录**画**出来，`秦领` 原样残留；同记录内 ASCII 代号 `QRCB` 已被 `XXXX` 替换。
- 根因：WMF 把**同一个文件名拆进两条文本记录**，切点落在「秦\|领」之间：
  ```
  @10136  META_EXTTEXTOUT  count=7   → "QRCB_秦"（GBK: 51 52 43 42 5f c7 d8）
  @10176  META_EXTTEXTOUT  count=44  → "领工程测试缺陷管理细则V1.7_202412031050.docx"
  ```
  `秦领` 的 GBK 4 字节 `c7 d8 c1 ec` 在文件里**从不连续出现**（中间隔 33 字节记录头），任何"整词字节替换"（=服务器 C1 现做法）都必然漏网。
- 方案（四个函数，整体挂载）：
  1. `_wmf_text_spans()`：解析 WMF（含可选 22 字节 placeable 头）`META_TEXTOUT(0x0521)` / `META_EXTTEXTOUT(0x0A32)`，返回字符串载荷区间（`rdSize` 以**字**计；EXTTEXTOUT 的 `Options & 0x0006` 时再跳 8 字节）。
  2. `_emf_text_spans()`：解析 EMF `EMR_EXTTEXTOUTA/W(83/84)`、`EMR_POLYTEXTOUTA/W(96/97)`（`offString` **相对记录头**）。
  3. `_redact_record_split_words()`：对**相邻两条文本记录**做前缀/后缀配对——敏感词 `w = head + tail`，若上一条以 `head` 结尾、下一条以 `tail` 开头，两段片段各自等长打码（GBK 1 字节/字、UTF-16LE 2 字节/字）。
  4. 编码判定：**先按 WMF 解析，失败再按 EMF 解析**——实测有 `.emf` 扩展名的文件其实是 WMF（农芯 `image19.emf`），只按扩展名派发会解错。
- 禁止项：**不要**退化成"对全文件做单字 GBK 兜底"——实测把农芯工程图表普通图注大面积误伤（`系统管理→管XX`、`第四轮→第XX轮`、`正常→正XX`，单文件多改 784 B）。

**E5. WMF/EMF 内「紧凑日期时间串」等长占位（`_mask_compact_datetime`）**
- 现象：E4 修完后，图标里仍留 `202412031050`（年月日时分）。原因是 WMF 内数字是 **ASCII 单字节**，而"年份 20xx→YYYY"只覆盖 **UTF-16LE** 形态；另外 UTF-16LE 侧 `20250120` 被年份规则**只切前 4 位**，输出半脱敏的 `YYYY0120`。
- 方案：在文本记录区间内，把"**整段连续数字恰好构成合法日期(时间)**"的串等长写成占位符：8 位 `YYYYMMDD`、12 位 `YYYYMMDDHHmm`、14 位 `YYYYMMDDHHmmss`。
  ```python
  _DT_RUN_RE = re.compile(r"^(?:19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])"
                          r"(?:(?:[01]\d|2[0-3])[0-5]\d(?:[0-5]\d)?)?$")
  ```
- **必须排在年份规则之前**：否则 UTF-16LE 的 `20250120` 先被切成 `YYYY0120`，尾部 `0120` 再也匹配不上"整串日期"。
- 刻意**不**处理（关键边界）：斜杠日期 `2025/10/17`、孤立年份 `2025`——排期甘特图里大量存在，属项目信息不属个人信息（农芯 `image19/21/52.emf` 共 100 处年份、98 处斜杠日期，零改动、逐部件字节一致）；也不**不要**把"年份规则原样扩展到 ASCII"（方案 E，已否）。
- 效果：《章程》`image16.wmf` → `XXXX_XX | XX工程测试缺陷管理细则V1.7_YYYYMMDDHHmm.docx`；《总体方案》`image4.emf` → `T第N轮-YYYYMMDD.xlsx`。

### I. 日期链（C12）

**D14. 日期链补"仅年份"形态（`(?<!\d)(20[12]\d)年` → `YYYY年`）**
- 上游现状：日期链覆盖 `YYYY年M月D日`、`YYYY年M月`、`YYYY-MM-DD`、8 位戳、两位年份 `YY/M/D`，但**没有"裸年份 + 年"**的规则——年份单独成词时整条链都不命中。
- 缺陷实证：
  - JRCB《UAT测试方案》s16 里程碑「上线 **2025年** 7月5日」——该处"上线 / 2025年 / 7月5日"分置**三个独立文本框**，单段内不存在"年M月"形态 → 年份漏脱（用户 2026-10-06 反馈）；
  - HTB 第五期 s26 甘特轴年度标签「**2021年**」「**2022年**」同类漏脱（审计漏检，本轮一并修正）。
- 方案：新增一行 `re.sub(r"(?<!\d)(20[12]\d)年", "YYYY年", text)`。
- **顺序陷阱**：必须排在 `YYYY年M月` 规则**之后**。若提前，`2025年7月5日` 会先被吃成 `YYYY年7月5日`，导致月日**失去补零对齐**（应为 `YYYY年07月05日`）。
- 兼容性：`2025年度`→`YYYY年度`、`2025年版`→`YYYY年版` 均符合"仅脱年"口径；`12025年` 因 `(?<!\d)` 不受影响。
- 实证：JRCB s16 唯一残留清零（run3→run4 仅 2 个 run 变更）；HTB 第五期重跑与已验收输出差异**仅 s26 两处裸年份**；三个历史 docx 存档复扫裸年份 0 处。

### J. 桂林 / 柳州 场景专用口径

**F1. 规范术语"银行结算账户"不是行名**
- `_GENERIC_BANK_RE` 会把「开立/变更/撤销**单位银行**结算账户申请书」吞成 `XX银行结算账户…`。冒号后紧跟 `结算账户` 时保留；`…银行部/室/处` 内部机构名同样豁免。
- 证据：柳州 docx 3 处恢复。

**F2. 表头圆括号限定词不构成"成句"**
- `测试经理（组长）` 被 `（）` 判成句 → 整列姓名不脱。剥离纯中文 1–4 字圆括号后再判列名（剥离后须以列名关键词结尾）。
- 证据：桂林 pptx 恢复 **49 名**（滑16×4、滑33×27、滑34×18）。

**F3. 机构列取值全局替换须设停用词**
- `全行/全辖/全省/全局/所有网点…` 作为《归属》列取值被全文替换 → 「全行模拟投产演练」误伤。
- 证据：柳州 docx 6 处恢复。

**F4. 姓名列复合格「标签：姓名标签：姓名」**
- 多组「系统：负责人」挤一格、组间无分隔符（`柜面：郑映成核心：崔雨濛`、`ESB：沈力柜面：李腾达`）。整格含冒号 → 纯汉字 fullmatch 不过 → 全格漏。**标签表按本文件预扫**（格首段=标签；中间段"姓名(2-4)+标签(2-6)"切分取后缀；**只收出现 ≥2 次的**以挡掉从姓名切出的伪标签），再按最长命中标签拆名打码、标签保留。
- 证据：桂林 pptx 滑32 5 格 **10 名**全打码。

**F5. 括号内的顿号不是分隔符**
- `李卓（水费、社保）` 按 `、` 切出 `李卓（水费` → 非纯姓名 → 首名漏。切分需括号感知：括号内**只**抑制 `、/，,；;`、**仍按空白切**（连空白一起抑制会把 `按需跑批（…Cycle Date…）` 去括号后剩 4 字被生僻姓兜底误打码）。
- 证据：桂林 pptx 滑33 1 名；docx 同口径移植零回归。

**F6. 姓名列取值的括号感知同样作用于"全局同名替换预扫"**
- 预扫切分若不括号感知，括号名单里的姓名漏入 `_EXTRA_NAMES`，正文引用处一并漏。
- 证据：随 F5 一并生效。

**G1. 人名段尾字豁免表须含「账」**
- 「核算业务组：负责账务核算、内部账、总账系统」里 3 字业务词「内部账」被当人名打成 XXX。真实姓名不以「账」结尾；全 8 源扫描所有「XX账」词段均为业务词（总账/对账/转账/平账/抹账/台账/内部账…）。
- 证据：柳州 docx 1 处还原。

### K. 工程化与通用缺陷警示

**H4. XML 属性值重写必须保留 `=`（所有历史交付件都带此 bug）**
- 现象：chart rels 里 `Target="file:///…xlsx"` 变成 `Target"file:///…xlsx`——**非法 XML**，lxml 直接解析失败。农芯 chart2/4/5 三处；**回扫发现 09-28/10-06/10-07 全部历史交付件同样带伤**（此前 sanity 只查 zip 完整性、不查 XML 可解析性，所以一直没暴露）。
- 根因：属性改写回调返回 `m.group(1) + '"' + new + '"'`——group(1) 是**属性名**（`Target`），把属性名与值之间的 `=` 丢了。正确写法 `m.group(1) + '="' + new + '"'`。
- **建议上游自查全部 `m.group(1)+'"'` 等价写法**，并把"全部件 XML 可解析性检查"纳入交付前 sanity（本次已加入本地 `sanity_check.py`，8 份输出 XML 100% 通过）。
