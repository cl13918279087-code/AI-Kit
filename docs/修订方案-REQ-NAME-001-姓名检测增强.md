## 一、现状分析

### 1.1 现有姓名检测架构

| 层级 | 名称 | 机制 | 覆盖 |
|------|------|------|------|
| L0（精确兜底） | `surname_pool + name_pool` 枚举 | 姓氏字 + 名字用字池两段组合正则 | 预设名单 |
| L1（正则通道） | `ROLE_WORD_PATTERNS`（entity_detector） | 角色词锚点 + 姓名捕获 | 已知角色格式 |
| L2（角色槽位） | `_ROLE_NAME_RE`（common_rules） | 角色前缀 + 姓名三件套（v1.3.9 R-㉙） | 调整记录句式 |
| L3（LLM） | `LLMClient` | 智能理解上下文（默认关闭） | 需配置开启 |

### 1.2 现有配置参数

- `surname_pool`：201 个姓氏字（含罕见姓）
- `name_pool`：152 个名字用字（单字/双字碎片）
- **根本局限**：name_pool 永远滞后，无法穷举真实姓名第二字

## 二、修订目标

在 **不退化现有精度**（G2 残留 0、误伤率 ≤+5%）的前提下，引入区域预判三层体系，将姓名覆盖率从 739 提升至 ≥1200（标准版 1249 的 96%，目标 +62%）。

## 三、修订方案：Layer N 区域预判体系

### Layer N-A：表格角色列检测（新增，P1）

**问题场景**：分工表/联络人表（如平安 PPT Slide 7/9-12/30-40）中姓名密集，单靠枚举无法覆盖。

**触发条件**：表格区域（XML `<a:tbl>`）列标题含角色词

**角色列词表**：
```
姓名、负责人、联系人、组长、组员、成员、主讲、汇报人、
审核人、审批人、编制人、修订人、修改人、复核人、联络人
```

**批量脱敏规则**：
1. 定位该列（及相邻 1~3 列，列宽 ≤ 6 字符）
2. 区域内所有 2~4 字符中文词块 → `XXX`
3. 排除表：`今日`、`昨日`、`一组`、`二组`、`三组`、`组长`、`组员`、`本组`、`各组`、`核心组`、`开发组`、`测试组`、`业务组`、`运维组`

**实施位置**：
- `redact_ppt.py`（PPTX XML 表格处理）
- `redact_excel.py`（XLSX 表格处理）
- 新增 `scripts/table_role_detector.py`

### Layer N-B：段落角色锚点扩散（新增，P1）

**问题场景**：段落含 `核心组：蔡新发、张瑜` / `组长张斌负责` 等格式。

**角色锚点词表（扩展 `_ROLE_NAME_RE` 现有词表）**：

```python
# 核心角色（高精度，冒号后扩散）
_CORE_ROLES = [
    "组长", "副组长", "项目经理", "技术负责人", "业务负责人",
    "项目总监", "架构师", "技术总监", "产品经理", "需求负责人",
]

# 通用角色（中等精度，冒号后扩散）
_GENERAL_ROLES = [
    "负责人", "联络人", "接口人", "审阅", "复核", "编制",
    "审核", "批准", "承办", "拟稿", "校对", "分发",
]

# 分组角色（顿号分隔名单）
_GROUP_ROLES = [
    "核心组", "开发组", "测试组", "业务组", "运维组",
    "项目组", "专家组", "评审组", "实施组",
]

# 排除短语
_ROLE_EXCLUDED = {
    "本组", "各组", "该组", "一组", "二组", "三组", "四组",
    "一组", "二线", "三线", "核心", "小组", "大组",
}
```

**扩散规则**：
1. 锚点命中后，判断分隔符类型
2. 冒号（`：：`）→ 捕获冒号后所有 2-4 字词块
3. 顿号（`、`）→ 捕获顿号分隔名单中的 2-4 字词块
4. 停止条件：遇到数字、`[（【`、英文为主区域

**实施位置**：
- `scripts/anchor_expand.py`（新增）
- 集成至 `common_rules.py` 的 `apply_redactions()` 后处理阶段

### Layer N-C：2-4 字密度扫描（新增，P2）

**问题场景**：分工表以外的人名密集区域，无预设规则时通用兜底。

**算法**：

```
density = 2-4字词块数量 / 区域内总字符数

IF density > 0.35 → 高密度，触发批量脱敏
ELIF density > 0.20 AND 含 surname_pool 姓氏 → 保守触发
ELSE → 不触发
```

**密度阈值标定**：

| 区域类型 | 典型密度 | 判定 |
|---------|---------|------|
| 人员分工表（姓名列） | 82% | 触发 |
| 正常正文段落 | 9% | 不触发 |
| 数字/编码列 | 3% | 不触发 |

**实施位置**：
- `scripts/density_scanner.py`（新增）
- 在 PPT/Word 每段/每行处理前预扫描

**风险控制**：
- 仅作用于 `redact_ppt.py` 和 `redact_word.py` 的正文段落（非标题）
- 排除含数字占比 >50% 的区域
- 排除含英文占比 >30% 的区域

### Layer N-D：surname_pool 区域扩散（改进现有，P2）

**问题场景**：姓氏命中后只脱紧邻 1~2 字，姓名密集区大量漏网。

**改进现有逻辑**：

```python
# 当前行为：
# surname + 后1~2字 → XXX

# 改进行为：
# surname + 后1~2字 → XXX
# + 同行/同列其他 2-4 字词块 → XXX
# + 停止条件：表头行/空白单元格/非中文为主区域
```

**实施位置**：
- `common_rules.py` `_build_patterns()` 中的姓名规则段

## 四、与现有规则的关系

```
Layer 0: name_pool 枚举（现有，精确匹配兜底，保留不动）
Layer 1: 区域预判 × 批量脱敏（新增，叠加，不替代）
Layer 2: surname_pool 区域扩散（改进现有）
Layer 3: LLM（现有，不变）
```

**核心原则**：新增规则均在主正则通道之后作为独立 pass 运行，互相叠加，互不干扰。

## 八、实施记录（v1.3.10）

> 2026-10-01 实施完成

### Phase 1：Layer N-A 表格角色列检测 ✅

**文件**：`scripts/table_role_detector.py`（新建）

**核心逻辑**：
- `_detect_role_columns_in_ppt_table()`：扫描表头行，含角色词则该列为角色列；角色列右侧所有非数字列一并纳入
- `_bulk_redact_chinese()`：批量脱敏 2-4 字中文词块（排除数字列/序号列/纯符号列/今日昨日等排除短语）
- `_rebuild_tc()`：用 `re.sub` 直接替换 `<a:t>` 内容，支持多 run 单元格
- `process_ppt_table_xml()`：处理 PPT `<a:tbl>` XML
- `process_xlsx_worksheet()`：处理 Excel 工作表 XML

**PPT 集成**：`redact_ppt.py` `_process_xml_file()`，在段落级处理前调用
**Excel 集成**：`redact_excel.py` `_process_xml_file()`，对 worksheet XML 调用

**检测关键词**：姓名/组长/成员/负责人/联络人/参与人/技术/管理等 30+ 词
**排除词集**：今日/昨日/一组/序号/项目名/金额等 32 项

### Phase 2：Layer N-B 段落角色锚点扩散 ✅

**文件**：`scripts/common_rules.py`（扩展）

**扩展内容**：
- `_ROLE_KEYWORDS_CORE`：项目经理/技术总监/架构师/产品经理/研发总监/安全负责人（6项）
- `_ROLE_KEYWORDS_GENERAL`：负责人/联络人/接口人/审阅/复核/编制/审核/批准/承办/协办等（14项）
- `_ROLE_KEYWORDS_GROUP`：核心组/开发组/测试组/业务组/运维组等（11项）
- `_apply_anchor_expand_pass()`：角色关键词+冒号后，顿号/逗号分隔名单批量脱敏
- `_ANCHOR_COLON_RE`：锚点正则（修正字符类语法，加入全部三组关键词）
- `_ANCHOR_EXCLUDED_NAMES`：排除"负责/协办/承办/今日/昨日/序号"等常见词
- `apply_redactions_counted()`：N-B pass 在 N-A pass 之后执行

**实测覆盖**：核心组顿号名单/组长单名/项目经理+动词后缀/参与人/协办人等 15 个场景全部通过
