> 版本：v1.0.0

## 一、项目背景与目标

### 1.1 项目背景

在金融行业项目实施过程中，存在大量需要对外分享或提交监管的文档材料。这些材料（如核心系统迁移方案、演练操作指南、需求文档等）通常包含：

- **银行名称**：涉及信息披露边界
- **人员姓名**：涉及个人隐私保护（姓名、手机号、身份证号等）
- **日期信息**：涉及商业敏感时间节点
- **账号/金额**：涉及金融数据安全
- **地址/IP 等**：涉及基础设施信息

手动脱敏效率低、易遗漏，需要构建自动化工具。

### 1.2 项目目标

构建一套**可配置的、批量化的、带有质量保障**的金融文档脱敏工具，支持 Word / Excel / PPT / PDF / 图片五类文档格式，集成 LLM 智能识别提升未知敏感词的发现能力，并生成可审计的脱敏报告。

### 1.3 约束条件

- 不涉及银行系统应用层数据，仅处理项目文档材料
- 脱敏结果需支持人工复核（通过对照报告）
- 工具需在项目现场可用（Windows / macOS / Linux）
- 处理过程不对原始文件产生影响（输入/输出分离）

## 三、检测机制设计

### 3.1 三层混合检测

**Layer 1 — LLM 智能检测**

- 使用 MiniMax-Text-01，temperature=0.05（低随机性）
- 自动分段（6000 字符/chunk，200 字符重叠）
- 识别未知业务词汇（银行名、系统名、产品名等规则无法覆盖的实体）
- 低置信度项（<0.75）标记为待人工确认

**Layer 2 — Regex 规则兜底**

- 覆盖所有标准格式：日期、手机、身份证、银行卡、邮箱、IP、MAC
- **链式顺序替换**：长文本先处理，短文本后处理（防止短文本误伤长文本）
- 关键修复：日期范围保留连接符（`YYYY/MM/DD 至 YYYY/MM/DD`）

**Layer 3 — 角色词上下文**

- 通过角色词（`联系人：`、`总行支持人员：`等）发现文档中具体人员姓名
- 排除词表防止误脱（`项目组`、`总行`等通用术语）

### 3.2 规则优先级

```
邮箱 → IP/MAC → 地址 → 身份证 → 银行卡 → 手机/固话 → 
日期范围 → 日期 → 银行名 → 组织名 → 人员姓名
```

## 四、各格式处理方案

### 4.1 Word（.docx / .doc）

**处理策略：**
- `lxml + zipfile` 直接读写 OOXML 内部 XML
- 完全绕开 python-docx 的高层保存逻辑（会合并 runs 导致格式丢失）
- 逐 `<w:t>` 节点替换，保留所有样式（标题/表格/页眉/页脚/批注）

**处理范围：**
- 正文段落、表格单元格
- 页眉、页脚
- 文本框（`wps:txbx`）
- 批注（`comments.xml`）
- 文档属性（`docProps/core.xml`）
- 嵌入图片文件名（含银行 Logo 关键词的图片替换为纯黑图）

**`.doc` 处理：**
- 通过 LibreOffice 转换为 `.docx` 后处理
- 转换失败时保留原文件（不破坏输入）

### 4.2 Excel（.xlsx / .xls）

**处理策略：**
- OOXML 直写（`xl/sharedStrings.xml` / `xl/worksheets/*.xml`）
- `.xls` 使用 `xlrd` 读取 + `xlwt` 写入

**处理范围：**
- 共享字符串表（Excel 最常用文本存储）
- 工作表单元格内联文本
- 批注
- 页眉页脚
- 文档属性

### 4.3 PPT（.pptx / .ppt）

**处理策略：**
- OOXML 直写（`ppt/slides/*.xml`）
- 媒体文件名脱敏（重命名含敏感词的图片/音视频）
- `.ppt` 通过 LibreOffice 转换

**处理范围：**
- 幻灯片正文（形状/文本框/表格）
- 幻灯片布局、母版
- 演讲者备注
- 媒体文件名（银行 Logo 检测）

### 4.4 PDF

**文本型 PDF：**
- PyMuPDF 提取带坐标文本（`page.get_text("dict")`）
- 在原位置绘制黑色矩形遮盖
- 在遮盖区域写入脱敏占位符（灰色小字）

**扫描版 PDF：**
- PyMuPDF 300 DPI 渲染为图片
- pytesseract OCR（含坐标的马赛克遮盖）
- OpenCV 启发式 Logo 检测（颜色方差 + 边缘密度）

### 4.5 图片

- pytesseract OCR 定位文字及坐标
- 正则识别敏感信息 → 马赛克/模糊/黑块遮盖（可配置）
- 银行 Logo 检测（OCR 找到"银行"→ 扩展左侧区域 → 颜色/边缘特征判断）

## 五、LLM 集成方案

### 5.1 支持的模型

| Provider | 模型 | 配置文件 key |
|----------|------|-------------|
| MiniMax | MiniMax-Text-01 | `minimax` |
| OpenAI | GPT-4o / GPT-4o-mini | `openai` |
| 智谱 | GLM-4 / GLM-4V | `zhipu` |

### 5.2 MiniMax API 配置

```json
{
  "llm": {
    "provider": "minimax",
    "model": "MiniMax-Text-01",
    "base_url": "https://api.minimaxi.com/v1",
    "api_key": "${MINIMAX_API_KEY}",
    "timeout": 120,
    "max_retries": 3
  }
}
```

### 5.3 LLM 使用策略

- **仅用于补充**：Regex 能覆盖的格式不用 LLM（节省 token、降低延迟）
- **低 temperature**：0.05，减少随机性，提高一致性
- **JSON Mode**：指定 `response_format: json_object`，减少解析错误
- **分段处理**：6000 字符/chunk，200 字符重叠，防止边界漏检
- **错误降级**：LLM 调用失败时记录警告，继续用 Regex 层兜底，不中断处理

## 六、批量处理与断点续传

### 6.1 批量并行

- 使用 `ProcessPoolExecutor`，默认 5 并行（可配置）
- 每个子进程独立处理一个文件，结果通过 Future 返回
- 主进程负责任务分发、进度更新、报告生成

### 6.2 断点续传

- 状态文件 `.redact_state.json` 记录已处理文件列表
- 中断后重新运行 `--resume`，自动跳过已完成文件
- 支持增量：新增文件只处理新增部分

### 6.3 进度展示

- `tqdm` 进度条：`{已完成}/{总数} [已用时间<剩余时间]`
- 实时显示成功/失败计数

## 七、质量保障

### 7.1 残留敏感词自检

脱敏完成后，对输出文件进行二次扫描，确认无残留：

```python
def residual_scan(text: str) -> List[str]:
    """扫描脱敏后文本中是否还有未处理的敏感信息"""
    patterns = [...]  # 关键正则
    residual = []
    for pattern, _ in patterns:
        matches = pattern.findall(text)
        residual.extend(matches)
    return residual
```

### 7.2 误脱检测

- LLM 二次验证：给定原始+脱敏文本对，检测误脱和漏脱
- 关键字段（身份证、银行卡）双重确认

### 7.3 对照报告

- JSON 格式：原始值 → 脱敏值完整对照
- Markdown 格式：可读性摘要报告（人读）
- 支持人工复核后导出存档

## 八、配置化设计

### 8.1 规则配置化

所有脱敏规则均可通过 `config.json` 调整，无需修改代码：

```json
{
  "bank_names": [...],       // 银行名列表（扩展/裁剪）
  "org_suffixes": [...],     // 组织名后缀
  "replacement": {...},      // 各类型替换占位符格式
  "surname_pool": "...",     // 百家姓池（姓名推断用）
  "exclude_patterns": [...]   // 排除词/排除正则
}
```

### 8.2 行业扩展

新增行业时，只需在 `config.json` 的 `bank_names` 中添加对应银行列表，`entity_detector.py` 的 LLM 层会自动识别上下文中的相关实体。

## 九、输出文件规格

### 9.1 文件命名

| 输入文件 | 输出文件 | 报告文件 |
|---------|---------|---------|
| `银行报告.docx` | `银行报告_脱敏.docx` | `银行报告_脱敏.docx_manifest.json` |
| 批量处理 | 同名 | `脱敏报告_YYYYMMDD_HHMMSS.md` |

### 9.2 报告格式

**Markdown 报告结构：**
```
# 文档脱敏批量处理报告
## 总体统计（成功/失败/跳过/耗时/敏感项总数）
## 按文件类型统计
## 成功详情（文件名 / 敏感项数 / 耗时）
## 失败详情（文件名 / 错误原因）
## 跳过详情
```

## 十、部署与运维

### 10.1 环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Python | >= 3.10 | 建议 3.11 |
| lxml | >= 4.9 | Word/Excel/PPT XML 处理 |
| openpyxl | >= 3.1 | Excel 处理 |
| python-pptx | >= 0.6 | PPT 处理（备选） |
| PyMuPDF | >= 1.23 | PDF 处理 |
| pytesseract | >= 0.3 | OCR |
| Pillow | >= 10.0 | 图片处理 |
| opencv-python | >= 4.8 | Logo 检测 |
| tesseract | 最新 | OCR 引擎（需单独安装） |

### 10.2 一键安装

```bash
pip install -r requirements.txt
# macOS
brew install tesseract tesseract-lang
# Linux
sudo apt install tesseract-ocr tesseract-ocr-chi-sim
```

### 10.3 升级策略

配置与代码分离，订阅更新时：
- `config.json` 变更 → 覆盖（用户需重新确认规则）
- `common_rules.py` 变更 → 覆盖
- `scripts/*.py` 变更 → 覆盖
- 用户自定义规则 → 保存在 `config.json` 中，不受更新影响

## 十一、技术风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| LLM API 不可用 | 中 | 低（Regex 兜底） | 降级到纯 Regex 模式，记录警告 |
| tesseract 未安装 | 中 | 高（图片/扫描 PDF 无法处理） | 启动时检测，提示安装命令 |
| LibreOffice 未安装 | 低 | 中（.doc/.ppt 老格式无法处理） | 检测提示，保留原文件不破坏 |
| 复杂格式文档误脱 | 中 | 中 | 人工复核报告，误脱反馈后调整规则 |
| 大文件（>50MB）处理慢 | 低 | 低 | 分块处理，不一次性加载到内存 |
