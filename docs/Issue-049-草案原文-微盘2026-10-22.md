## 上游问题（可复现样例，已脱敏）

**环境**：Windows 11 / Python 3.13 / 纯正则模式（未配置 LLM Key）/ 默认 `config.json`（`surname_pool` 415 字、`name_pool` 1285 字、`full_name_list` 7398 个）

**复现方式**

```python
import sys; sys.path.insert(0, "scripts")
import common_rules as cr
print(cr.apply_redactions_counted("本次会议由陈黎主持，蔡元龙记录，天阳宏业7人参会。")[0])
```

**实测结果（v1.4.0 main 默认配置）**

| # | 原文 | 实际输出 | 期望输出 | 判定 |
|---|---|---|---|---|
| 1 | 天阳宏业7人参会 | 天**XXX**7人参会 | 天阳宏业7人参会 | 厂商名被吞 |
| 2 | 811工程项目组 | XX工**XXX**目组 | XX工程项目组 | 「程项目」被当人名 |
| 3 | 全功能白盒测试 | 全**XXX**盒测试 | 全功能白盒测试 | 测试术语被吞 |
| 4 | 蔡元龙记录 | **XXX**录 | 蔡XXX记录 | 3 字名吞掉第 4 字「记」 |
| 5 | 成员：李思远、周慧敏、王根利负责需求 | 成员：XXXXXXXXXXXX | 成员：XXX、XXX、XXX负责需求 | 名单整段被当 4 字名，分隔符丢失 |
| 6 | 昆明分行完成投产切换 | **XX分行**完成投产切换 | XX分行… | ✅ 本项为修正（旧版误成「昆明XXXX」） |
| 7 | 本次会议由陈黎主持 | 本次会议由**XXX**主持 | 同左 | ✅ 本项为 Issue #45 收益（旧版漏脱） |

**归因（逐字符定位，新池 vs 旧池）**

| 误伤词 | 命中通道 | 触发字符（新增于新池） |
|---|---|---|
| 天阳宏业 | 姓氏`阳` + 名字池`宏业` | `阳` 新入姓氏池（旧版无） |
| 811工程项目组 | 姓氏`程` + 名字池`项目` | `程` 新入姓氏池 |
| 全功能白盒 | 姓氏`全` + 名字池`功能` | `全/能` 新入池 |
| 蔡元龙记录 | 姓氏`蔡` + 名字池`元龙记` | `记` 新入名字池，且允许 3 字名 |

结论：问题不在 `full_name_list`（7398 精确全名通道表现良好，陈黎/王根利均能命中），而在 `surname_pool 201→415`、`name_pool 152→1285` 扩张后，`[姓氏][名字池 1~2 字]` 这条通用枚举正则开始大面积命中业务复合词。

**影响面**

- 金融/政务类文档中「天阳宏业」「工程项目组」「全功能白盒」「记录」「对账」等高频词被部分吞字，输出可读性下降，需人工回改；
- 脱敏方向为「过度」，不构成漏脱合规风险，但属于质量回归；
- 该配置为用户开箱默认值，非个例。

## 改进方案

**方案 1（建议优先，改动最小）：名字池分档**

`config.json` 增加：

```json
{ "name_pool_mode": "base" }
```

- `base`（默认）：沿用 201 字姓氏池 / 152 字名字池，行为等同 v1.3.10；
- `extended`：启用 415 / 1285 大字池（本次扩张值）。
- 大字池的真实收益主要在 `full_name_list`，与字池扩张解耦后可两全。

**方案 2：业务词排除表下沉为配置**

`config.json` 增加 `name_stop_words: []`，加载时并入 `_ANCHOR_EXCLUDED_NAMES`。

现状是排除词只能改 `common_rules.py` 内的硬编码集合，与《社区运行模式》"只改一处、不改原版"冲突——各成员环境无法在不产生副本漂移的前提下收敛误伤。

**方案 3：命中后二次校验**

枚举通道命中后，若不在 `full_name_list` 内，则要求至少一条上下文证据才脱敏：±8 字内出现角色词（组长/成员/负责人…）、或命中小节标题含「人员/名单/签字」、或该词在全文出现 ≥2 次且形态一致。无证据则保留。

**方案 4：边界与最长匹配**

- 名字匹配后补 `(?![\u4e00-\u9fa5])` 或改用「`full_name_list` 最长匹配优先」，避免 3 字名吞第 4 字（样例 4）；
- 名单枚举（`、`/`，` 分隔）在替换时保留分隔符与角色词前缀（样例 5）。

**影响面**：单文件/单规则（`common_rules.py`）+ 配置（`config.json`），不涉及处理器层。
