# 内网部署指南（企业内网 Agent）

> 适用对象：在企业内网搭建 / 运维 Agent 的技术团队
> 目标平台：内网自建 Agent（OpenClaw 类形态）、离线或半离线环境
> 配套工具：`scripts/doctor.py`（安装自检）、`scripts/build_package.py`（分发包构建）

---

## 一、部署形态与总体流程

```
[开发侧]                          [内网侧]
git 仓库                          分发包 zip
   │                                  │
   │ build_package.py                 │ 校验 SHA256
   │                                  │ 解压到 skills/doc-redact/
   │                                  │ pip install -r requirements.txt
   │                                  │ doctor.py 自检 ←── 门禁
   │                                  │ Agent 装载 SKILL.md
```

**关键原则**：**装载 → 自检 → 投产**。跳过自检是最常见的事故来源——
内网机器缺 OCR 二进制、缺 Python 包、LLM 端点配成公网地址，这些在开发机
全部不可见，只会在处理真实文档时才暴露。

---

## 二、准备分发包

### 2.1 构建（开发侧）

```bash
# 最小运行集（推荐）
python3 scripts/build_package.py --outdir ./dist

# 连测试与 CI 一起打包（内网需自测时）
python3 scripts/build_package.py --include-dev
```

产物：

| 文件 | 用途 |
|---|---|
| `doc-redact-<version>.zip` | 技能包本体 |
| `doc-redact-<version>.zip.sha256` | 完整性校验（内网验签） |
| `doc-redact-<version>.manifest.json` | 内容清单：逐文件 SHA256 + 依赖声明 |

### 2.2 分发包内容边界

分发包**不含**以下开发期资产（`build_package.py` 默认剥离）：

- `tests/`、`docs/`、`.github/` —— 测试、CI、评审文档
- 挖掘类脚本（`mine_*.py`）、迭代对比类脚本（`redact_iterative_*.py`）
- 质量门禁脚本（`bench_metrics.py` 等，留在开发侧执行）
- 个人语料目录（`工作目录/`、`共建项目/`、`output/`）

包内仅保留 Agent 运行必需文件 + 安装说明 + 许可文件。

### 2.3 真实人名清单处理

`scripts/config.json` 的 `full_name_list` 是从业务语料抽取的自然人姓名列表
（约 7400 条）。它是姓名规则字频自举的种子数据，但也是**分发侧 PII 风险点**。

三种处置口径：

| 口径 | 做法 | 适用 |
|---|---|---|
| **A. 保留内联**（默认） | 不做处理 | 内网受控分发、包不外流 |
| **B. 外置注入**（推荐） | 配置 `full_name_list_file` 指向本行花名册 | 内网投产 |
| **C. 脱敏打包** | `build_package.py --strip-pii` | 包需跨环境流转 |

口径 B 的配置（`scripts/config.json`）：

```json
{
  "full_name_list_file": "data/bank_roster.txt"
}
```

文件格式：**每行一个姓名**，`#` 开头为注释行。路径解析顺序为
`$AIKIT_DATA_ROOT/` → 技能包根 → `scripts/` → 相对当前目录。

合并语义：内联列表 ∪ 外置文件（外置优先、去重保序）。
外置文件缺失时**静默回退**到内联列表，既有行为完全不变。

口径 C 要求已配置 `full_name_list_file`——否则脱敏后姓名召回会显著下降，
工具会直接拒绝打包，避免交付「看着干净但能力残缺」的包。

## 三、内网侧安装

### 3.1 校验完整性

```bash
sha256sum -c doc-redact-1.0.0.zip.sha256
```

### 3.2 解压到 Agent 技能目录

```bash
# 目录名须与 SKILL.md 的 name 一致：doc-redact
mkdir -p /opt/agent/skills/doc-redact
unzip -q doc-redact-1.0.0.zip -d /opt/agent/skills/doc-redact
```

### 3.3 安装 Python 依赖

```bash
cd /opt/agent/skills/doc-redact

# 内网有 PyPI 镜像
pip install -r requirements.txt -i http://pypi.intra.bank/simple

# 或离线 wheelhouse
pip install --no-index --find-links=/path/to/wheelhouse -r requirements.txt
```

> **离线镜像制作**：在一台能访问外网的同版本机器上执行
> `pip download -r requirements.txt -d wheelhouse`，将 `wheelhouse/`
> 与分发包一并移交内网。

依赖分两类：

- **必装**（缺失则对应功能完全不可用）：`lxml`、`requests`、`tqdm`
  —— 其中 `tqdm` 是 `pipeline.py` 的**顶层 import**，缺失会导致
  `import pipeline` 直接失败，属"装完即崩"的典型项。
- **可选**（缺失则对应能力降级）：其余全部。

完整清单见 `requirements.txt`；开发/测试依赖单独在 `requirements-dev.txt`。

### 3.4 安装外部二进制

Python 包体系覆盖不到的外部程序须由运维离线安装：

| 二进制 | 用途 | 缺失后果 | 安装建议 |
|---|---|---|---|
| `tesseract`（+ `chi_sim` 语言包） | 扫描版 PDF、图片 OCR | 扫描件与图片脱敏不可用 | `apt install tesseract-ocr tesseract-ocr-chi-sim` |
| `LibreOffice` | `.doc` / `.ppt` 格式转换 | 旧格式降级到 `antiword` / `textutil`，**表格结构可能丢失** | `apt install libreoffice-writer` |

> `.doc` 转换链为三级降级：LibreOffice → textutil（macOS 自带）→ antiword。
> 内网 Linux 环境通常只有 LibreOffice 与 antiword，textutil 不可用属正常。
> 降级发生时会在 manifest / 批量报告 / 退出码中留痕，**须人工复核**。

安装路径非标准时，用环境变量指定：

```bash
export SOFFICE_PATH=/opt/libreoffice/program/soffice
```

### 3.5 安装自检（**必做门禁**）

```bash
cd /opt/agent/skills/doc-redact
python3 scripts/doctor.py
```

输出示例：

```
A. Python 运行时
  ✅ 版本 — 3.11.9
B. Python 依赖
  ✅ lxml — 5.2.2
  ⚠️ pytesseract — 未安装
      → 可选依赖：pip install pytesseract —— 缺失时 扫描件 OCR 不可用
C. 外部二进制
  ✅ OCR 引擎 — /usr/bin/tesseract
...
总计 36 项：通过 28，提示 1，告警 7，失败 0
⚠️ 存在告警项：功能可运行，但相关能力降级，须确认影响面
```

判定与处置：

| 退出码 | 含义 | 处置 |
|---|---|---|
| `0` | 全部通过 | 可投产 |
| `1` | 必装项缺失 / 端点不合规 | **禁止投产**，按提示补齐后重跑 |
| `2` | 告警项（可选能力缺失） | 可投产，但须书面确认降级影响面 |
| `3` | 自检无法执行 | 检查参数与路径 |

机器可读输出（供 Agent 编排或流水线门禁消费）：

```bash
python3 scripts/doctor.py --json
```

```json
{
  "worst_status": "warn",
  "counts": {"ok": 28, "info": 1, "warn": 7, "fail": 0},
  "checks": [{"group": "...", "name": "...", "status": "warn", "detail": "..."}]
}
```

严格模式（告警也视为失败，用于投产流水线硬门禁）：

```bash
python3 scripts/doctor.py --strict
```

## 四、Agent 装载与调用

### 4.1 技能注册

Agent 从技能目录读取 `SKILL.md` 的 frontmatter 完成注册：

```yaml
name: doc-redact
display_name: 文档脱敏
description: "文档脱敏技能包：对 Word、PPT、Excel、PDF、图片中的敏感信息做遮盖与匿名化处理……"
author: hui.zhao18
department: "BUCON"
Version: V0.0.1
Usage_scope: 云端本地都能使用
version: 1.0.0
requires_python: ">=3.9"
requires_binaries: [tesseract, soffice]
license: MIT
```

> **字段分工**：`Version`（对外发布标识，形如 `V0.0.1`）与 `version`
> （内网装载契约字段，须为可解析 semver，供 Agent 做升级/回滚判定）并列存在，
> 不可互相替代——`scripts/build_package.py` 只读小写 `version` 决定分发包名与
> manifest 版本号，误删会导致分发包版本回退。

### 4.2 包根定位

技能包内所有脚本以 `__file__` 自解析包根，**不依赖当前工作目录**。
Agent 侧建议在会话初始化时解析一次并缓存：

```bash
SKILL_ROOT=/opt/agent/skills/doc-redact
```

### 4.3 典型调用

```bash
# 单文件
python3 "$SKILL_ROOT/scripts/redact_word.py" <输入> <输出>

# 批量（推荐入口，含并行 / 断点续传 / 自动报告）
python3 "$SKILL_ROOT/scripts/pipeline.py" <输入目录> -t all -o <输出目录> --workers 4
```

退出码语义（`redact_all.py` / `pipeline.py` 一致）：

| 退出码 | 含义 |
|---|---|
| `0` | 全部成功，且无降级产物 |
| `1` | 存在**失败**文件（无产物）——**失败优先于降级** |
| `2` | 无失败，但存在**降级产物**（须人工复核） |

## 五、LLM 端点合规

### 5.1 定位

本技能包是 **Agent 技能包**，LLM 调用能力由 **Agent 侧**承载，
脚本侧 LLM 通道默认关闭（`config.json` 的 `llm.enabled = false`）。

脚本侧守卫（`scripts/llm_egress.py`）只管得住**脚本自带**的 LLM 客户端通道；
**Agent 直处理模式**用的是 Agent 侧配置的端点，不在仓库守卫管辖内。

### 5.2 Agent 侧端点自检（必做）

```bash
python3 "$SKILL_ROOT/scripts/endpoint_check.py" \
    --base-url https://llm-gw.corp.bank.local/v1
```

判定口径与脚本侧守卫**同源**：scheme 须为 http/https，且 host 命中
`allowed_hosts` 白名单**或**为内网地址（私网 IP / localhost /
`.internal` / `.lan` / `.corp` 等）。

退出码：`0` = 全部合规；`2` = 存在不合规端点；`3` = 参数或配置错误。

**不合规即不得使用直处理模式处理生产文档**，须先改端点或补白名单。

### 5.3 脚本侧 LLM 通道（可选）

若需开启，在 `config.json` 的 `llm` 段配置：

```json
{
  "llm": {
    "enabled": true,
    "provider": "openai-compatible",
    "model": "your-internal-model",
    "base_url": "https://llm-gw.corp.bank.local/v1",
    "api_key": "${INTERNAL_LLM_API_KEY}",
    "allowed_hosts": ["llm-gw.corp.bank.local"],
    "require_private_network": true,
    "pre_redact_before_llm": true
  }
}
```

- `base_url` **无公网默认值**，必须显式配置；
- `api_key` 支持 `${ENV_VAR}` 插值，**不要把密钥写进文件**；
- `pre_redact_before_llm` 保持 `true`：送 LLM 前先做等长掩码，
  避免个人唯一标识进入 LLM 上下文；
- 未配置或校验不通过时，脚本**降级为纯规则检测**，绝不发起外网请求。

## 六、数据目录与权限

| 目录 | 内容 | 建议权限 |
|---|---|---|
| `<输出目录>/.redact_work/` | 中间产物（灰区评审 JSON、转换临时件） | `0700` / 文件 `0600` |
| `<输出目录>/` | 脱敏产物、manifest、脱敏报告 | 按密级管理 |
| `$AIKIT_DATA_ROOT/` | 外置数据（人名库等） | 只读，按密级管理 |

中间产物由 `scripts/workdir.py` 统一管控：统一落盘、权限收紧、
任务结束显式清理（异常路径由调用方 `try/finally` 兜底）。

## 七、升级与回滚

1. **版本标识**：每次发布同步更新 `SKILL.md` frontmatter 的
   `Version`（对外发布标识，如 `V0.0.1`）与 `version`（semver，供 Agent
   升级/回滚判定），并重建分发包（包名含版本号）。
2. **升级前留档**：保留旧版 zip 与 manifest，便于回滚。
3. **升级后必跑自检**：`python3 scripts/doctor.py`，退出码须为 `0` 或
   已确认的 `2`。
4. **回归验证**：开发侧 `bench_metrics.py` 八项门禁全 PASS 后方可发布；
   内网侧建议在真实语料上抽样复核（重点看姓名召回与通用语料误伤）。
5. **配置迁移**：升级时注意 `config.json` 新增键的默认值——
   新键缺失一律回退到"安全默认"（如 LLM 通道保持关闭）。

## 八、常见问题

| 现象 | 原因 | 处置 |
|---|---|---|
| `import pipeline` 报 `No module named 'tqdm'` | `tqdm` 未装（顶层 import） | `pip install tqdm` |
| 图片 / 扫描件脱敏报 OCR 不可用 | `tesseract` 二进制缺失 | 离线安装 tesseract + `chi_sim` |
| `.doc` 处理后表格丢失 | 走了 `antiword` 降级链 | 安装 LibreOffice；核对退出码 `2` 与降级清单 |
| 姓名召回明显下降 | 外置名单为空或格式错误 | 核对 `full_name_list_file` 路径与每行一名格式 |
| 脚本从任意目录调用失败 | 直接 `cd` 到包根的写法 | 用 `$SKILL_ROOT/scripts/...` 绝对路径 |
| 端点自检报不合规 | Agent 侧端点为公网地址或不在白名单 | 改内网端点或补 `allowed_hosts` |
