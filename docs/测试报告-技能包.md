### 2.2 受限环境适配（仅测试侧，不涉及产品代码）

本轮执行环境为受限沙箱，存在两项与产品无关的硬限制：

1. **禁止删除临时文件**——`tempfile.gettempdir()` 的可用性探针（建文件 → 删文件）必然失败，
   导致任何使用 `tempfile` 的子进程（含 `pipeline` 的 spawn 工作进程）崩溃；
   `openpyxl` / `python-docx` 保存时删除中间文件抛 `PermissionError`。
2. **子进程写入受限**——`textutil` / `soffice` 转换产物报「You don't have permission」。

适配措施（`.tmpwork/`，属测试辅助物，**不进入版本库**）：
以 `sitecustomize.py` 经 `PYTHONPATH` 注入，提前指定 `tempfile.tempdir`，
并将 `os.remove` / `os.unlink` 的 `PermissionError` 降级为忽略；
测试驱动脚本补 `if __name__ == "__main__":` 保护（spawn 契约）。

## 五、缺陷清单

### 5.1 产品缺陷（本轮发现并全部修复）

| 编号 | 分级 | 现象 | 根因 | 修复 | 验证 |
|---|---|---|---|---|---|
| **D-01** | P1 | `count_redactions()` 对任何输入均抛 `ValueError: not enough values to unpack (expected 2, got 1)` | 函数体残留死代码 `for (key,), (pattern, _) in zip([[k]…], [[p]…]])`：右列表仅 1 元素却按 2 解包；且类别标签按「规则序号 → `REDACTION_LABELS` 下标」映射（40+ 规则 vs 14 标签，根本不对齐） | 重写为复用 `apply_redactions_counted()`，标签与遮盖口径同源 | TC-L1-04 转绿 |
| **D-02** | P1 | 损坏 / 空 / 截断 docx 直接抛裸 Python 栈；不支持格式（`.txt`）退出码 0 且写出**伪 manifest** | `redact_all.redact_file` 的 except 分支直接 `traceback.print_exc()`；`handler is None` 时返回 `{}`（与「成功但 0 处遮盖」不可区分） | 契约改为 `None` = 失败/不支持（`{}` = 成功但 0 处）；置失败标志；错误输出两行可读信息（`AIKIT_DEBUG=1` 才开栈）；`write_redaction_manifest` 调用加 `if counts is not None:` 守卫 | TC-L5-03/04/05/07 转绿 |
| **D-03** | P1 | 缺 `opencv-python` / `numpy` / `pytesseract` 时，**连用法提示都崩溃**（模块级 `import cv2` 直接失败） | `redact_image` 在模块顶层导入三个可选依赖 | 改为延迟导入 + `_require_cv2` / `_require_np` / `_require_pytesseract` 三守卫（错误信息含离线 wheelhouse 指引）；`main()` 增加可读异常与退出码 2/1 分级 | TC-L5-01 转绿 |
| **D-04** | P1 | `RedactResult.manifest_path` 是**虚假路径**——只拼接字符串从不落盘，下游按该字段取留痕会拿到「文件不存在」 | `pipeline` 未实现 manifest 写盘 | 新增 `_write_manifest()`：真实落盘 `manifest.json` + `manifest.md`，返回真实 json 路径；声明与事实一致（要么真实落盘，要么返回空串）；5 个 `_process_*` 补齐 `counts` 回传 | TC-L4-11 转绿 |
| **D-05** | P1 | `redact_all -o <目录>` 产出**无扩展名**文件，且 manifest 落到目录之外 | `_resolve_output_path` 仅识别「已存在目录」与「尾斜杠」两种目录语义 | 输出参数语义扩展为三判据：已存在目录 / 尾斜杠 / **无扩展名即目录语义** | TC-L4-12 转绿 |
| **D-06** | P1 | `redact_all.py` **语法错误**：`SyntaxError: name '_LAST_FILE_FAILED' is assigned to before global declaration` → 整条 CLI 链路不可用（一度致 24 个用例失败） | `global` 声明位于函数中部、晚于对该名字的首次赋值 | `global _LAST_FILE_FAILED` 上提至 `redact_file()` 首行，删除中部重复声明 | 全量转绿 |
| **D-07** | P2 | 文档与实现口径不一致：README / 实施手册称「固定电话 / 组织名 / 地址已禁用」，实际**仅银行卡号禁用**（固话 `0XX-XXXXXXXX` 全遮、ORG 由 `org_suffixes` 驱动、地址按层级遮盖均为启用） | 文档未随 R-D 社区决策与实现同步 | 以实现为准修正 README 版本对照表与实施手册脱敏范围表，并同步用例断言口径 | 文档 + TC-L1-03 一致 |
| **D-08** | P2 | `--resume` 状态文件默认落 **CWD**（`.redact_state.json`），污染调用方工作目录（Agent 场景 CWD 常为用户数据目录），同一次运行多次调用互相覆盖 | `pipeline` 参数默认值硬编码 | `--resume-state` 默认值改为 `None`，落点改为 `<输出目录>/.redact_state.json` | TC-L3-05 转绿 |

### 5.2 测试侧问题（用例 / 环境自身，非产品缺陷）

| 编号 | 现象 | 处置 |
|---|---|---|
| E-01 | 测试驱动脚本缺 `if __name__ == "__main__":` → spawn 子进程重新导入主模块并**重跑整轮套件** → 进程池崩溃报 "A process in the process pool was terminated abruptly" | 补 `__main__` 保护（spawn 契约；产品侧 `pipeline.batch_process` 的调用方同样必须遵守） |
| E-02 | 测试辅助函数**覆盖** `PYTHONPATH`，导致 CLI 子进程未加载环境适配 shim → 报 "No usable temporary directory found" | 改为**追加**而非覆盖，保留继承路径 |
| E-03 | pytest 复用旧 `--basetemp` 目录触发删除权限错误 → 大批量 `ERROR at setup` | 每次执行使用全新 basetemp；该噪声消除后 `test_pipeline_status_consistency` 15 项由「9 ERROR」转为全通过 |
| E-04 | 用例自身 10 处假设与实现不符（固话口径、ISO 正则、掩码形态、kwargs 传参、resume 落点、报告章节名、只读目录、分发包结构、`doctor.py` 正则为检测模式非路径残留等） | 逐一修正用例断言，不改产品行为 |

| 级别 | 风险 | 缓解 |
|---|---|---|
| 中 | **LLM 层未经真实推理网关验证**：仅验证了「默认不出网 / 守卫判定 / 预脱敏不外泄原文 / 端点合规口径」，未验证内网网关真实返回质量与偏移对齐 | 上线前在目标内网做一次小样本联调；`premask` 等长掩码已保证偏移一致 |

## 七、投产结论

1. **功能与安全结论**：核心链路（Word / Excel / PPT 三类主载体 + 编排 + 审计 + 装载）功能正确、
   行为确定、幂等，**未发现明文泄漏、假脱敏、越权写入**；本轮发现的 8 项缺陷（P1×6、P2×2）已全部修复并回归通过。
2. **门禁结论**：八项准出门禁全部 PASS，规则层精度/召回指标无劣化（recall 100%、precision 99.9%、真实语料误伤 0/1200）。
3. **有条件通过**：建议按下列顺序完成剩余事项后正式投产——
   - **必做**：在目标内网机器补跑 U-01~U-05 五项未覆盖区（装齐 `pymupdf` / `pytesseract` / `opencv-python` / `numpy` / `xlrd` / `xlwt`）；
   - **必做**：以目标内网 LLM 推理网关做一次端到端联调，确认预脱敏与返回偏移对齐；
   - **建议**：将本轮 69 项专项用例纳入 CI，与既有门禁脚本合并为每次提交的必跑项。
4. **变更影响面**：本轮改动仅涉及 `scripts/common_rules.py`、`scripts/redact_all.py`、`scripts/redact_image.py`、
   `scripts/pipeline.py`、README 与实施手册，**未改变任何脱敏规则的口径与阈值**（仅文档口径向实现对齐），
   对既有业务语料的脱敏结果零影响（`通用语料改动 2/102` 且均为「设计意图」类非姓名类改动，姓名类 0/102）。
