# Issue #52 职务与称谓式人名识别通道 — 落地方案

> 状态：**已落地**（`main` @ `4228f5b` 之后合入）· 关联上游 Issue #52（AI-Kit）
> 上游诉求：#52 原始诉求中「职务/称谓形态（刘主任/王总/小李/李工）与昵称前缀尚未实现」，
> 本方案即为该遗留项的完整实现。

## 一、问题定位

既有规则层只有「姓名规则」一条通道能识别人名，**姓 + 职务后缀**（刘主任/王总/李工/张经理）、
**昵称**（小李/老李）、**单字姓 + 动词边界**（会议由刘主持）三类形态全部漏脱。

但这三条形态**不能**做成全局匹配——一旦全局粗筛，「总工」「施工」「分段」「项总」等
**姓 + 后缀业务词**会成片误伤（#49 P0 的核心教训）。因此 #52 的关键不在「加一条规则」，
而在**加一条区域化的规则**。

## 二、三形态定义

| 形态 | 示例 | 判定要点 |
|---|---|---|
| 姓 + 职务后缀 | 刘主任 / 王总 / 陈总 / 李工 / 张经理 | 实证姓 + 职务后缀，且通过保护词包含语义校验 |
| 昵称 | 小李 / 老李 | 昵称前缀 + **D16 实证姓首字集合**（393 字） |
| 单字姓 + 动词边界 | 会议由刘主持 | 单字姓后紧邻动词/职责锚点，不做全局匹配 |

### 2.1 D16 实证姓约束（为什么不用姓氏池）

姓氏池 415 字里包含大量**伪姓氏**（如「经」）。若昵称通道直接用姓氏池，
「老经理」会被切成「老经 + 理」而误命中。本通道改用
`full_name_list`（7398 条实证全名）**首字集合**（393 字）作为实证姓来源，
从源头排除「老经」这类伪姓氏。

## 三、区域化口径（#52 §3.4）

称谓形态**只在角色锚点附近生效**：

- **左锚点**
  - 组织锚点字：部 组 处 室 科 队 班 所 司 厂 园 院 行
  - 请求动词：请 派 由 让 交 经 据 和 与 及 同
- **右锚点**（职责动词）
  - near（紧邻）：负责 牵头 主持 发言 讲话 审批 把关 带队 汇报 报告 说明 介绍 总结 宣读 点名 莅临 列席 陪同 加班 到位 督办 调研 检查 推行
  - far（窗口 ≤6）：到会 参会 出席 前来 到访 赴会

这正是 #49「全局粗筛教训」的直接应用。

## 四、保护词包含语义（#52 §3.1 关键约束）

- `EXCLUDED_COMMON_WORDS` 与 `common_word_guards` **仅在「保护词 ⊇ 命中片段」时豁免**
  （span ⊆ phrase）；
- **禁止反向豁免**——否则 `主任` ∈ EXCLUDED 会连带放过「刘主任」，
  直接违背 §3.1；
- `config.json` → `title_suffix_names.skip_phrases` 走**双向**包含豁免，
  覆盖「支行长 / 副行长 / 总行长 / 分行长 / 施工 / 完工 / 加工 / 工休」等
  姓 + 后缀业务词；
- 命中片段本身即保护词（「经理」独立成词）同样豁免。

## 五、实现落点

- 规则入口：`scripts/common_rules.py` → `_apply_title_name_pass()`
  （主链位于 `_apply_address_pass` 之后、`name_patterns` 之前）
- 配置：`scripts/config.json` → `title_suffix_names`
  （suffixes / nickname_prefixes / org_anchor_chars / left_anchor_words /
  role_verbs_near / role_verbs_far / nickname_block_followers /
  title_modifier_chars / single_char_exclusions / skip_phrases）
- 辅助：`_get_title_suffix_re()` `_get_title_nick_re()` `_get_title_single_re()`
  `_title_span_blocked()` `_title_left_anchor()` `_title_right_anchor()`
  `_get_attested_surnames()`
- 替换策略：多形态匹配 → 去重叠 → 从后往前替换为 `XXX` → `counts["姓名"] += 1`
