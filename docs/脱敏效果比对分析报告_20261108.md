## 二、比对方法学

### 2.1 三方参照系

```
   源文件 (src)  ──── 参照系 ────►  人工标准脱敏版 (std)
        │                              ▲
        │  SequenceMatcher 对齐        │ S = std 遮盖的源片段集合
        ▼                              │
   本程序产物 (mine) ──────────────────┘ M = mine 遮盖的源片段集合
```

对每个文本块做 `difflib.SequenceMatcher` 序列对齐，求出「相对源文件被替换的片段集合」：

| 集合 | 定义 | 业务含义 |
|---|---|---|
| `S ∩ M` | 双方都遮盖了 | ✅ **一致遮盖**（程序有效） |
| `S \ M` | 标准版遮了、程序未遮 | ⚠️ **漏脱**（程序不足） |
| `M \ S` | 程序遮了、标准版保留 | ⚠️ **过度脱敏**（程序误伤） |

其中 `S \ M` 再按「该原文片段是否仍以原文形式存在于产物中」二次分流为：
- **真实漏脱**（`still_in_mine=True`）：原文仍可见 → **合规红线**
- **形式漏脱**（`still_in_mine=False`）：程序用了不同占位符或不同切分 → 可用性/一致性问题

### 2.2 五个辅助维度

| 维度 | 含义 | 阈值 |
|---|---|---|
| D2 占位符一致性 | 同一片段两侧替换符是否相同 | 供参考 |
| D4 结构保真 | 块数、有效字符数差异 | 字符偏差 ≤ ±5% |
| D5 残留复扫 | 用独立正则复扫产物中的手机号/身份证/邮箱/卡号/IP/银行名 | **0 命中为达标** |
| 对齐率 | 源文件非空块中被三方共同覆盖的比例 | ≥ 95% |
| XML 结构完整性 | 产物能否被 Office/python 库打开 | **必须可打开** |

### 2.3 文本抽取链路

| 格式 | 抽取方式 |
|---|---|
| `.pptx` | python-pptx，按 slide 分块（含表格单元格） |
| `.docx` | python-docx，按段落 `pN` / 表格单元格 `tN` 分块 |
| `.xlsx` | openpyxl，按 `sheet!cell` 分块 |
| `.doc` | **纯 Python OLE2/FIB 片段表解析**（新增 `scripts/doc_ole_text.py`） |

> **本轮工程修复**：G3 组的三个 `.doc` 文件中，**源文件是真 OLE2 二进制，而「标准版」与「产物」实为 OOXML（docx）格式但扩展名为 `.doc`**。此前按扩展名走 LibreOffice 转换，导致转换静默失败、G3 比对完全失效（块数 0/0/0）。现已改为**按魔数嗅探真实格式**：PK 开头按 OOXML 解析，D0CF11E0 开头走纯 Python OLE2 解析。

## 四、漏脱分析（合规红线，95 处）

### 4.1 根因归类

| 根因 | 处数 | 代表样本 | 机制说明 |
|---|---:|---|---|
| **A. 人名不在名单库** | ~20 | 孙海刚、吴文静、王谧、俞曦、刘兆缋、李义申、旭辉、乐平、凌晨 | 7400 人 `full_name_list` 未收录；`rule_a_enabled=false`（规则A 已退出主链路），仅靠 N-C 区域层 + D16 精确匹配 + 上下文锚点召回 |
| **B. 人名在名单库但无上下文锚点** | ~14 | 欧暁烨、张锦宇、李熔 | 同上，且不在名单区（表格姓名列 / 正文名单段 / 签名落款区）内 |
| **C. 机构/品牌名未覆盖** | ~11 | 平安（平安科技南京 / 平安信用卡） | `config.json → bank_names` 仅含 `郑州银行/海峡银行/中原银行`，**未含 `平安银行`**；且非银行名的「平安科技」类主体名无规则 |
| **D. 地名 / 网点名** | ~2 | 八卦岭 | 无通用地名脱敏规则（`LOCATION` 占位符存在但未接线到具体规则） |
| **E. 测试口令** | ~12 | 123123、456456、888888 | `密码` 规则要求「密码 + 6 位以上数字」紧邻匹配，**独立出现的纯数字口令**未覆盖 |
| **F. 部门简称 / 业务术语** | ~4 | 计财、信用卡全链路 | 简称无字典 |
| **G. 数字片段（日期/编号）** | ~32 | 3、10、29、44、60、136 | 段落级对齐粒度导致的标准版切分差异，多为形式漏脱 |

### 4.2 关键判定

**根因 A/B 是本次最重要的发现。** 程序当前依赖「名单库 + 区域上下文」双闸门召回人名，而**正文叙述中的人名**（"XX行长指示…"、"XX总提出…"）既不在 7400 人库中，也不处于名单区内——这两道闸门同时失效，导致完全漏脱。

这正是 §5 中「过度脱敏」的镜像：**闸门开得太紧**（区域外一律不动）**与** 名单库覆盖不足叠加，使正文人名成为系统性盲区。

### 4.3 整改建议

| 优先级 | 措施 | 预期收益 |
|---|---|---|
| **P0** | 扩充 `full_name_list`（补入本次实测漏脱的 11 个姓名，并从源文档反向抽取全量人名候选） | 直接消除根因 A |
| **P0** | 启用**「职务锚点前置」召回**：`name_anchor_words.role` 已含「行长/组长/经理/负责人」等锚点，但仅在锚点**之后**匹配；需补充**锚点前置**形态（"由XX行长"、"XX行长指示"） | 覆盖根因 A 中的职务型人名 |
| **P0** | 补齐 `bank_names`：加入 `平安银行`；并新增「非银行主体名」通道（如「XX科技」「XX保险」等主体后缀） | 消除根因 C |
| P1 | 新增**独立数字口令**规则：独立单元格/段落中 6–8 位纯数字且上下文为「口令/密码/初始密码」语义 | 消除根因 E |
| P1 | 新增**网点/地名**规则（结合 `LOCATION` 占位符） | 消除根因 D |
| P2 | 部门简称字典（计财、零售、网金等） | 消除根因 F |

## 六、结构保真与产物可用性

### 6.1 字符数偏差

全部七组偏差在 **−1.56% ~ +3.79%** 区间，远优于 ±5% 阈值。G1 的 +3.79% 来自占位符长度差异（本程序 `XXX` 3 字符 vs 标准版 `XXX` 但切分粒度不同）。

### 6.2 本轮修复的 P0 缺陷：XML 结构破坏（已闭环）

**缺陷现象**：PPT/Word/Excel 处理器的**整文件级兜底通道**对 XML 原文整体跑正则，属性名 `spd="slow"` 命中拉丁银行缩写 `SPD`（上海浦东发展银行）被替换为 `[Bank]`，产出**非法 XML**，12 个 slide 损坏，python-pptx 与 Office 均无法打开。

**修复方案（哨兵保护）**：
1. 将标签名与属性名替换为含 `\x00` 控制字符的不可命中哨兵；
2. `xmlns:*` 声明整体保护（名称 + 值），避免 `urn:abc` 中 `abc` 被误判为银行缩写导致 URI 非法；
3. 整份 XML 一次性脱敏（**保留文档级上下文**，这是 N-C 名单区域检测等通道的依赖前提）；
4. 事后还原哨兵。

> 期间曾尝试「逐节点拆分」方案，因破坏文档级上下文导致姓名召回从 444 掉到 63，已废弃。

**验证结果**：
- G1 姓名召回 **444 = 444**，与修复前完全一致，零回归；
- 七组产物 XML 零损坏，PPTX/DOCX/XLSX 全部可正常打开；
- 新增 `tests/test_xml_structure_preservation.py`（10 项）作为回归护栏，含「召回无损失」断言。

### 6.3 新增工程能力：纯 Python `.doc` 解析兜底

**问题**：内网离线环境 / 受限沙箱中，LibreOffice 常因 profile 不可写抛 `DeploymentException`；`textutil`/`antiword` 依赖外部二进制。转换链全败时 `.doc` 完全无法脱敏。

**方案**：新增 `scripts/doc_ole_text.py`，纯 Python 解析 OLE2 Compound Document：
- FIB 定位 `fcClx`/`lcbClx`（偏移 `0x01A2`/`0x01A6`）与 `ccpText`（`0x004C`）；
- 依 `fWhichTblStm`（FIB `0x000A` bit9）选择 `1Table`/`0Table` 流；
- 解析 `Clx` → `PlcPcd` 片段表，按 `FcCompressed` bit30 区分 cp1252 单字节与 UTF-16LE。

**实测**：真 OLE2 语料（83 页 / 6442 词）成功提取 **40720 字符、648 段落**，零外部依赖。

**接入**：作为 `.doc` 转换链的 **L2.5 `ole-python` 级**（LibreOffice → textutil → antiword → **ole-python**），已实测在 LibreOffice/textutil/antiword 全不可用时成功产出可打开的 `.docx`。安全约束沿用既有口径：该级**丢失格式与表格结构**，必须标记 `degraded_level` 并列入人工复核清单。
