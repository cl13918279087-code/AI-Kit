## 一、本轮定位：#50 落地后的残余漏脱

#50 把 N-C 区域检测层编码落地后，格式适配层仍存在**四类结构化漏脱**——共同点是
「真名确实在表里，但判定链没有把它认出来」。本轮把这四类通道补齐：

| # | 漏脱类型 | 现象 | 根因 |
|---|---|---|---|
| 1 | **PPT 网格列错位** | slide40/48 的子列真名（谈叙/朱丽芸/邓君/陈瑜/胡璐/董欣/李虎/戚亚亚）**18 处整片未脱** | 物理 `<a:tc>` 下标 ≠ 表头逻辑列（`gridSpan="4"` + `hMerge="1"`） |
| 2 | **占位符稀释一致率** | 「捞数需求方（对接人）」列整组未命中 | 子表头行「运营/风险/市场/技术」与 `--` 占位把一致率稀释到 0.375 < 0.4 阈值 |
| 3 | **行向结构漏脱** | slide40/48「捞数执行人」行（行标签即人角色）整行泄漏 | 列向判定不命中（该表以行为单位组织人信息） |
| 4 | **无角色表头姓名列** | slide47「业务所属」列（陈柯/胡璐/唐雨晨/董欣/杨城鑫/刘宇牵头）泄漏 | 表头无人角色词 → T1 通道完全不触发 |

另有一类**规则层必然漏掉**的名单外真名（名字位字不在 D16 库）：陈鲲/吴县波/
成新华/官民/陈沈麟/桂宾/叶助茂/候睿/华盛 等——这些在 A/B/C 级字频闸门下
**结构上无法命中**，需要一个基于**文档级词频**的 D 级补漏通道。

## 二、落地内容

### 2.1 D 级补漏通道（稀有字真名）

**核心洞察**：业务词在全文中**反复出现**，姓名基本**只出现一次**。这一条
文档级分布特征，正好可以把「首字恰是姓氏」的常用词挡在 D 级之外。

新增 `scripts/name_region_detector.py`：

```python
_NC_DOC_FREQ_MAX = 8          # 文档级 gram 频次上限（≥8 视为高频词，挡住）
_NC_DOC_GRAM: Optional[Dict[str, int]] = None

def build_nc_doc_gram(texts) -> Dict[str, int]   # 统计 CJK 2~3 gram 频次
def set_nc_doc_gram(gram) / clear_nc_doc_gram()    # 注入 / 清空（防跨文档污染）
def _nc_tier_d(token) -> bool                      # 姓首 + 低频(<8) + 非业务词
```

D 级闸门（三条全部满足才成立）：

1. token 为 **2~3 字纯中文**（含 ASCII 的串不计入）；
2. 首字落在**姓氏集合**（含 D 级专用池外姓「印」）；
3. **文档级 gram 频次 < 8**——业务词几乎必然超此值；
4. token 本身不在角色标签表、不在业务词保护表。

**保守设计**：未注入文档级上下文（`set_nc_doc_gram` 未调用）时，**D 级整体不启用**。
理由：没有文档级证据就没有低频判据，宁可漏脱也不误伤业务词。

**接线点**（`scripts/redact_ppt.py`）：PPT 在处理 slide 前，先用
`_PPT_TEXT_RE` 抽取全量 `<a:t>` 文本统计 gram 并注入；`finally` 中清空，
避免跨文档污染。

D 级实现在真实语料中新增遮盖 **2 处**（荆田田、彭鲁摇），**均为真名，无一误伤**。

### 2.2 PPT 逻辑列展开（gridSpan / hMerge）

新增网格解析（`scripts/table_role_detector.py`）：

```python
_PPT_GRIDSPAN_RE = re.compile(r'gridSpan="(\d+)"')
_PPT_HMERGE_RE   = re.compile(r'hMerge="1"')

def _ppt_grid_width(tbl_xml) -> int                              # <a:gridCol> 数量
def _ppt_row_cells(row_xml) -> List[(起始列, 跨列数, 文本, 是否续接)]
def _ppt_row_groups(cells, grid_w) -> List[(起始列, 跨列数, 文本)]  # 合并列组
```

规则：

- 按 `gridSpan` **累计**得到每个单元格的逻辑起始列；
- `hMerge="1"` 的续接单元格**不占新列**，只映射到左侧锚点列；
- 一个表头 `gridSpan="N"` 单元格 = 一个**列组**，组内成员列拼接后再做形态判定。

**列组池化**是解决第 2 类漏脱的关键：一致率按**列组**统计而非单列，
`--` 占位符与子表头不再稀释分母。修复后该列组确认率从 0.375 提升到 **0.75**，
落入 relaxed 档命中。

### 2.3 全员姓名列通道

表头**没有**人角色词、但取值几乎全是姓名——这类列原判定链完全不触发。新增：

```python
def detect_name_only_columns(header_cells, data_rows,
                             min_values=3, min_ratio=0.9,
                             max_header_len=12) -> Dict[int, str]
```

命中条件（四条全满足）：

1. 该列**纯中文取值** ≥3 个（`_nc_pure_name_value` 允许尾部角色词后缀：
   「牵头/负责/主导/跟进/承接/协办/经办/owner」）；
2. 取值长度 **2~3 字**、命中率 **≥90%**；
3. 表头长度 **≤12 字**；
4. 表头**不命中业务词保护表**。

实测全文档命中面仅 **3 处**（s47t0 col3 全员姓名列 + s40t1/s48t1 行向通道），
**全部正确**。

### 2.4 行标签人角色通道

首列是人角色标签时，该行其余单元格按 A/C 级强证据脱敏。三重闸门
（任一不满足即不触发）：

```python
_NC_ROW_PERSON_TAIL_RE = re.compile(r"(?:人|负责人|联系人|组长|副组长|owner|Owner|OWNER)$")
```

1. 表头整体确有人角色词（`is_person_header`）；
2. 首列标签以**人角色词尾**收尾；
3. **该行确有姓名证据**（避免「总行业务实施组」这类组织标签误触发）。

### 2.5 伪表头行排除

新增 `_nc_row_name_ratio(cells)`：候选表头行若「值形态像姓名」的单元格占比
**≥50%**，则**不作为表头**处理。

原因：行向结构里以「捞数执行人」开头的那一整行取值全是姓名，若被误判为表头，
整行会被跳过 → 反而制造新的漏脱。

### 2.6 业务词前缀防护（同步修复既有回归）

前序新增的 B 级「中文前缀猜测」会把「渠道拓展」误判成姓名「渠道」→
产出「XXX拓展」；A 级最长前缀若命中业务词表会误遮「白名单用户」的「白名」。
本轮加两条约束：

- **A 级**：最长前缀若命中业务词表 → **整个 token 不作姓名**（不回退短前缀）；
- **B 级**：**不做中文前缀猜测**，只在「整体就是 2~3 字姓名」或「姓名 + 非中文括注」时启用；
  `_relaxed_name_span` 同步加「命中段之后若接中文则不算」的保护。

该修复同时让既有断言 `test_detect_name_columns_t1` 恢复通过。

### 2.7 列确认率口径修正

```python
def _nc_confirm_ratio(values) -> float   # 分母只计纯中文 token
```

`--`、`CRS中提取`、含 ASCII 的串**不计入**分母——这些是占位符/代号，
计入会把确认率稀释到阈值以下。
