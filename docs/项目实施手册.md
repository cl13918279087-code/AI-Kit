# 文档脱敏项目 — 实施手册

> 版本：v1.0.0
> 适用场景：金融/银行项目文档批量脱敏

---

## 一、环境准备

### 1.1 快速检查

```bash
# 检查 Python 版本（需要 >= 3.10）
python3 --version

# 检查核心依赖
pip show lxml openpyxl python-pptx PyMuPDF Pillow pytesseract 2>/dev/null | grep Name

# 检查 tesseract（OCR 引擎，必须安装）
tesseract --version 2>&1 | head -1
```

### 1.2 安装步骤

**Step 1：安装 Python 依赖**

```bash
cd ~/Projects/doc-redact-project
pip install -r requirements.txt
```

**Step 2：安装 Tesseract OCR（macOS）**

```bash
brew install tesseract tesseract-lang
# 验证安装
tesseract --version
```

**Step 3：安装 Tesseract OCR（Linux）**

```bash
sudo apt update && sudo apt install tesseract-ocr tesseract-ocr-chi-sim
```

**Step 4：安装 LibreOffice（处理 .doc / .ppt 老格式，可选）**

```bash
# macOS
brew install --cask libreoffice
# Linux
sudo apt install libreoffice
```

**Step 5：配置 LLM API Key**

```bash
# 方式1：环境变量（推荐）
export MINIMAX_API_KEY="your-api-key"

# 方式2：编辑 config.json
# 将 "api_key": "${MINIMAX_API_KEY}"
# 改为 "api_key": "your-actual-api-key"
```

## 二、基本使用

### 2.1 单文件脱敏

```bash
python3 pipeline.py ~/Documents/银行报告.docx -o ~/output
```

**输入：** `~/Documents/银行报告.docx`
**输出：** `~/output/银行报告_脱敏.docx`

### 2.2 文件夹批量脱敏

```bash
# 脱敏 docs 目录下所有支持格式的文件
python3 pipeline.py ~/Documents/docs -t all -o ~/output --workers 5
```

### 2.3 指定文件类型

```bash
# 只处理 Word 和 PDF
python3 pipeline.py ~/Documents/docs -t word,pdf -o ~/output

# 只处理图片
python3 pipeline.py ~/Documents/docs -t image -o ~/output
```

**类型选项：** `word` | `excel` | `ppt` | `pdf` | `image` | `all`

### 2.4 启用断点续传

如果在处理过程中中断（如 Ctrl+C 或断电），可以继续：

```bash
python3 pipeline.py ~/Documents/docs -t all -o ~/output --resume
```

已处理完的文件会被自动跳过，未处理完的继续执行。

### 2.5 覆盖已有输出

```bash
python3 pipeline.py ~/Documents/docs -t all -o ~/output --overwrite
```

## 三、输出文件说明

### 3.1 输出目录结构

```
~/output/
├── 银行报告_脱敏.docx              # 脱敏后的 Word 文档
├── 银行报告_脱敏.docx_manifest.json  # 该文件的详细脱敏清单（JSON）
├── 演示文稿_脱敏.pptx
├── 演示文稿_脱敏.pptx_manifest.json
├── 脱敏报告_20260813_143022.md     # 批量处理汇总报告（Markdown）
└── .redact_state.json              # 断点续传状态（--resume 时生成）
```

### 3.2 报告内容

**Markdown 汇总报告包含：**
- 处理文件总数、成功/失败/跳过数量
- 按文件类型分组统计（处理数、敏感项数、原始大小）
- 每个文件的详细处理结果
- 失败原因（如有）

## 四、自定义配置

### 4.1 添加银行名

编辑 `config.json`，在 `bank_names` 数组中添加：

```json
"bank_names": [
  "中国工商银行",
  "中国农业银行",
  ...,
  "我的目标银行"   ← 添加这一行
]
```

### 4.2 调整替换占位符

编辑 `config.json` 中的 `replacement` 部分：

```json
"replacement": {
  "NAME": "XXX",          // 人员姓名
  "BANK": "XX银行",       // 银行名称
  "DATE": "YYYY/MM/DD",   // 日期格式
  ...
}
```

### 4.3 调整并行数

默认 5 并行处理，根据机器性能调整：

```bash
# 低配机器用 2 并行
python3 pipeline.py ~/docs -t all -o ~/output --workers 2

# 高配机器用 10 并行
python3 pipeline.py ~/docs -t all -o ~/output --workers 10
```

### 4.4 禁用 LLM 增强

如果不需要 LLM 辅助识别（节省 API 调用、加快速度），编辑 `config.json`：

```json
"redaction": {
  "llm_enabled": false
}
```

## 五、常见问题排查

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| `ModuleNotFoundError: lxml` | 依赖未安装 | `pip install -r requirements.txt` |
| `tesseract not found` | Tesseract 未安装 | `brew install tesseract tesseract-lang` |
| `.doc` 文件内容未脱敏 | LibreOffice 未安装 | `brew install --cask libreoffice` |
| LLM 检测返回空 | API Key 错误/网络问题 | 检查 `MINIMAX_API_KEY` 环境变量 |
| 输出文件格式错乱 | 原始文件是假 .docx（WPS 创建） | 用 WPS 另存为真 .docx 再处理 |
| 脱敏后图片丢失 | 嵌入 OLE 对象被跳过 | 这是已知限制，手动确认 OLE 内容 |
| 进度条卡住 | 大文件处理耗时 | 等待或查看日志中的具体文件进度 |

### 5.1 查看详细日志

```bash
# 显示 DEBUG 级别日志（包含每个文件的处理详情）
python3 pipeline.py ~/docs -t all -o ~/output -v
```

### 5.2 验证脱敏结果

打开输出目录中的 `_manifest.json` 文件，查看具体哪些内容被脱敏了，对照原始文档人工复核。

## 六、安全注意事项

1. **输出文件与输入文件分离** — 原始文件不修改，输出到独立目录
2. **API Key 保护** — 不要将包含真实 API Key 的 `config.json` 提交到代码仓库
3. **脱敏报告存档** — 脱敏报告建议随文档一起存档，便于后续审计追溯
4. **敏感信息不打印** — 日志中不输出原始敏感信息内容

## 七、日常使用场景

### 场景1：迁移项目交付前批量脱敏

```bash
# 将项目文档目录一次性脱敏
python3 pipeline.py ~/项目/核心系统迁移/docs -t all -o ~/交付物/脱敏版 --workers 5 --resume
```

### 场景2：定期更新文档脱敏

```bash
# 增量处理（新文档才处理，已处理的跳过）
python3 pipeline.py ~/项目/docs -t all -o ~/output --resume
```

### 场景3：只处理某一种格式

```bash
# 只需处理 PDF
python3 pipeline.py ~/项目/docs -t pdf -o ~/output
```
