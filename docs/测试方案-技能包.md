## 一、测试目标

本方案面向「银行内网 Agent 装载技能包」这一最终交付形态，验证四件事：

1. **功能正确性**——对 Word / Excel / PPT / PDF / 图片五类载体，敏感信息是否被正确遮盖，
   非敏感信息是否被误伤（脱敏的两条腿：漏脱与误脱，缺一不可）。
2. **合规安全性**——是否会发生「未脱敏原文出网」，审计链（manifest / 报告 / 退出码）
   是否真实可信，是否存在明文泄漏到产物中的路径。
3. **健壮性与异常处理**——面对内网真实环境里的畸形输入（损坏文件、截断文件、超大文件、
   恶意压缩包、路径穿越、不支持格式），是「优雅失败」还是「崩溃 + 假成功」。
4. **可装载性与一致性**——分发包在干净目录可用、自检工具结论可信、
   同一输入多次处理结果一致（确定性 / 幂等）。

**核心判定原则**：宁可失败并说明原因，**不得静默失真**（生成名为「脱敏」但内容未脱敏的产物、
吞掉异常后返回成功、声明了审计产物却从不落盘）。

## 三、测试分层与矩阵

采用「六层 + 一横切」结构，每层有独立判定标准：

```
┌─────────────────────────────────────────────────┐
│ L6 装载一致性层：分发包在干净目录可运行           │
├─────────────────────────────────────────────────┤
│ L5 CLI 契约层：参数、退出码、stdout/stderr 语义   │
├─────────────────────────────────────────────────┤
│ L4 端到端层：真实文件 → 真实产物 → 内容校验        │
├─────────────────────────────────────────────────┤
│ L3 编排层：批量、并发、断点续传、状态机            │
├─────────────────────────────────────────────────┤
│ L2 模块层：规则引擎 / 守卫 / 预脱敏 / 审计组件      │
├─────────────────────────────────────────────────┤
│ L1 单元层：纯函数行为（规则、脱敏、掩码、统计）     │
└─────────────────────────────────────────────────┘
        ↕ 横切：安全合规（明文泄漏 / 出网 / 越权）
```

**横切维度**（每层都需考虑，不是独立一层）：

- **明文泄漏**：脱敏产物（含 zip 内所有条目、docProps、manifest、报告）中不得出现原文片段。
- **出网边界**：任何 LLM 通道开启前必须过出网守卫；守卫判定与文档口径同源。
- **越权与注入**：不得写出输入目录之外的路径；不得执行文档内嵌内容。

## 七、缺陷分级

| 级别 | 定义 | 举例 |
|------|------|------|
| P0 致命 | 导致假脱敏、明文泄漏、越权写入、或核心链路不可用 | 产物仍含原文明文；解压越权写文件 |
| P1 严重 | 功能错误或契约违背，影响正确性与可审计性 | manifest 声明路径不存在；统计函数抛异常 |
| P2 一般 | 体验/健壮性问题，不影响正确性 | 错误信息不够可读；退出码语义不精确 |
| P3 轻微 | 文档/注释/风格类 | 注释与实现不符 |

## 八、风险与约束

1. **PDF 文本层与图片 OCR 未覆盖**——本机缺 `pymupdf` / `pytesseract` / `opencv-python`，
   该两条链路的功能验证依赖内网环境补齐依赖后复测，报告中列为遗留风险。
2. **`.xls` 未覆盖**——依赖 `xlrd` / `xlwt`。
3. **LLM 层未真实调用**——内网网关不可达，以守卫与预脱敏 Mock 替代；
   真实调用的实体识别质量需在内网联调时验证。
4. **性能阈值为相对值**——绝对耗时随机器差异大，仅作数量级判断。
5. **沙箱环境限制**——临时文件删除受守卫拦截，测试统一用 `--basetemp` 独立目录规避。
