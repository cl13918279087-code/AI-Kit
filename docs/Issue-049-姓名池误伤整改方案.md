# Issue #49 整改方案：姓名池扩张误伤分级治理

> Issue：https://github.com/cl13918279087-code/AI-Kit/issues/49
> 贡献人：赵辉
> 状态：**方案已定，P0 已落地，P1 待社区评审**
> 关联：#45（姓名池扩充）、#42（R4 评分层）、#38（D8/D11 角色槽位）、#48（差异归因修正）

---

## 一、问题定性

Issue #45 将 `surname_pool` 196→415 字、`name_pool` 152→1285 字后，**规则A 字符池粗筛**的可匹配模式空间从 ≈3 万扩至 ≈53 万（**18×**）。超出真实人名增量的部分全部是日常汉语常用字，与业务词汇高度重合，导致大面积无效替换。

**关键归因**：误伤几乎全部来自规则A，**D16 精确匹配层本身是 #45 的正确设计**（104 条语料仅 1 条误伤，且"高明"属人名/词义双解、人名场景正确）。因此 #45 的数据资产与 D16 规则**不需回滚**，需改造的是规则A。

## 三、根因

### 3.1 三层检测的职责边界在扩池后失衡

| 层 | 规则 | 匹配依据 | 扩池后表现 |
|---|---|---|---|
| 精确层 | D16 `full_name_list` | 7398 已知全名（枚举） | 误伤 **1.0%**，召回可靠 |
| 粗筛层 | 规则A `姓 + [name_pool]{1,3}` | 415×1285 笛卡尔积 | 误伤 **54.8%** ⬅️ 问题主体 |
| 兜底层 | R4 评分层（jieba + 6 特征） | 上下文语义 | 未启用（`name_mode` 默认 enum） |

### 3.2 高危单姓与常用词首字正面碰撞

415 姓中大量本身即常用词首字：`成 方 平 常 和 田 米 干 车 费 贝 何 余 刁 卜 危 安 宁 尚 甘 习 靳 莫 孔 老 庄 荀 孟 单 关 解 应 宗 丁 宣 邓 洪 包 诸 左 石 崔 吉 钮 龚 林 门 龙 段 郑 牛 浦 施 零 厉 刘 …`

这些姓氏 + 常见字几乎必然组成真实存在的词：`成本/成立/成功/成员`、`渠道`、`流程`、`日常/业务`、`单元/元宇宙`、`温州/宁波/江苏`。

### 3.3 无右边界约束放大了破坏范围

规则A 自 Issue #5 起为防漏脱敏已移除 `(?![a-zA-Z0-9])`，贪婪量词 `{1,3}` 会一路吃到后续汉字，"渠道拓展"整个 4 字被替换。

## 四、整改方案：三层置信分级（方案 R）

### 4.1 设计原则

**误伤与漏脱不对称** —— 漏脱属合规红线，误伤属可用性缺陷。分级策略以"高置信直接脱敏 / 中置信需上下文佐证"分层，**不做无差别收紧**。

### 4.2 规则集

| 层 | 规则 | 触发条件 | 置信 | 动作 |
|---|---|---|---|---|
| **R1** | D16 精确表 | 命中 `full_name_list` | 高 | 直接脱敏 |
| **R2** | 低危姓 + 2~3 名字字 | 姓氏 ∉ `high_risk_surnames` | 中 | 直接脱敏 |
| **R3** | 高危姓 + 3 名字字 | 姓氏 ∈ `high_risk_surnames`，需三字全名 | 中 | 直接脱敏 |
| **R4** | 上下文锚点 + 任意姓 + 1~2 名字字 | 角色词/名单邻域 | 中 | 脱敏 |

**上下文锚点词表**（复用 #38 D8/D11 角色槽位）：
`负责人 / 联系人 / 成员 / 人员 / 组长 / 经理 / 主任 / 总监 / 名单 / 参会 / 出席 / 签名 / 签字 / 汇报 / 由 / 请 / 联系 / 支持人员 / 配合人 / 经办人 / 办理人 / 授权人 / 审批人 / 复核人 / 申请人 / 填报人 / 签字栏`

### 4.3 参数网格搜索结果

以"误伤最少 + 真名召回最多"为目标，对 `(低危姓 min~max, 高危姓 min~max, 是否启用锚点)` 做全网格搜索（2×3×2×2×2 = 48 组）：

| 排名 | 配置 | 误伤 | 真名 | 漏脱真名 |
|---|---|---|---|---|
| 1 | 低危 2~1 / 高危 3~3 / 锚点 | 4 | 7 | 王小红、张明、樊霖、司马光、李雷 |
| 2 | **低危 2~2 / 高危 3~3** | **9** | **9** | 张明、樊霖、李雷 |
| 3 | 低危 2~3 / 高危 3~3 | 9 | 9 | 张明、樊霖、李雷 |
| 4 | 低危 2~1 / 高危 2~2 | 14 | 9 | 张明、樊霖、李雷 |

**选定配置：低危姓 `{2,3}` + 高危姓 `{3,3}` + 上下文锚点**。理由：

- 排名 1 的"低危 2~1"是空区间（等价于关闭低危规则），虽误伤最低但漏脱 5 个真名，**违反"漏脱优先于误伤"的红线**
- 排名 2/3 在误伤 8.7% 前提下把真名召回从 7 提到 9，漏脱仅剩 3 个**二字名**
- 漏脱的 3 个（张明/樊霖/李雷）在真实场景几乎总伴随角色词上下文，由 R4 锚点覆盖：

| 场景 | 结果 |
|---|---|
| 负责人：张明 | ✅ 脱敏 |
| 参会人员李雷 | ✅ 脱敏 |
| 请樊霖办理 | ✅ 脱敏 |
| 由李雷签字 | ✅ 脱敏 |
| 总行支持人员：张明 | ✅ 脱敏 |
| 组长是樊霖 | ❌ 漏脱（"是"字未列入锚点连接符）|

### 4.4 残余误伤与归属

分级后残余 9 条误伤，全部属**词义消歧**范畴，不应在正则层硬编码：

| 残余误伤 | 性质 |
|---|---|
| 渠道拓展、单元测试、元宇宙、客户经理 | 通用词，需 R4 语义评分 |
| 宁波银行、甘泉资本、江苏卫视 | 机构名，需银行/机构名规则先行 |
| 高明、叶子涵 | 人名/词义双解，人名场景正确 |

**处置建议**：优先把机构名规则（银行名/城市名）调整到姓名规则**之前**执行，可消解"宁波银行/甘泉资本"2 条；其余交 R4 评分层（#17）仲裁。

### 4.5 性能

| 指标 | 数值 |
|---|---|
| 分级方案单次全文替换 | **0.45 ms** |
| 相对当前实现 | 无退化 |

### 主要风险与缓解

**风险**：收紧后"名单外人名"召回下降。

**缓解**：
1. R4 上下文锚点覆盖角色词邻域场景
2. R4 评分层（#17）作二道仲裁
3. D16 精确表保持 7398 全量，名单内人名零漏脱
4. 回归测试 `test_true_name_recall` 设召回下限 **8/12**，低于即 CI 失败
