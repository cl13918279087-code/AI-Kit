> 状态：**P1 已实施并关闭**（回评评论已发布，issue 已 closed）
> 关联：#50（规则A 退出主链路，本层为 §10.7 提出的遗留缺口）、#49（姓名池误伤 P0 教训）、#51（占位名层，同为词表型名单层）

## 〇、问题定性：这是**词典覆盖缺口**，不是规则设计缺口

#50 §4.8 退出门槛达成后，规则A 笛卡尔积通道（R2/R3）已退出主链路（提交 `b3aa5c6`），
遗留一个明确边界：**「孤立 + 无上下文锚点 + 不在 D16 精确库」的 2 字名**（如「王明」）不再被全局脱敏。

根因定位：

> D16 全名库（`full_name_list`，7399 条含「姓名」污染项，实际 7398）**不是通用人名词典**，
> 而是**本项目语料里实际出现过的姓名**。实测抽查 86 个高频中文人名
> （王明/黄磊/吴刚/徐静/孙悦/胡军/郭强/何伟…），**66 个不在库中（缺失率 77%）**。

因此任何靠**形态**（笛卡尔积 / 粗筛）去补的方案都会重新引入 #49 的误伤放大器。
#50 收尾时已实测否决「40 高频姓 × 名字位热字」收紧版笛卡尔积（630 组参数扫描）：
虽在 102/1200 语料上达标，但误伤靠 `common_word_guards` / `standalone_exempt_words`
词表兜底而非判据本身，「高效/高度/陈述/章程」类词在现有语料中几乎不存在，
放行即在未见文本上大面积误伤。

**本层的定位因此是：用一份「精确词表」替代「形态推导」**，把覆盖缺口从规则层挪到数据层。

## 二、准入漏斗（证据收窄，五级）

原始 120W 语料不能直接入层，逐级收窄：

```
原始 120W 姓名语料
  ↓ ① 形态：仅保留 2 字 / 3 字且全汉字
  ↓ ② 姓氏位：限 D16 实证姓氏集（392 字）——不靠"高频姓"启发式
  ↓ ③ 名字位：限 D16 实证字频
  │     T2（2 字名）：尾字频次 ≥ 10
  │     T3（3 字名）：两个名字位字频均 ≥ 30
  ↓ ④ T3 追加证据要求：尾 2 字 ∈ T2 ∪ D16（避免生造三字名）
  ↓ ⑤ 去重剔除：D16 全名库 / 豁免表 / 保护表 / 业务词 / 占位名（placeholder_names）
  ↓ ⑥ 双语料「独立成词片段」剔除（102 通用语料 + 1200 真实业务语料）
117201 条（T2 66162 + T3 51039）
```

关键设计说明：

- **② 姓氏位限 D16 实证姓氏集**（392 字）而非「百家姓」启发式——D16 是本项目语料的**实证**姓氏来源，
  避免引入无证据的姓氏位。
- **③ 名字位字频同样取自 D16 实证字频**，保证名字位用字在本项目真实出现过。
- **④ T3 的「尾 2 字 ∈ T2 ∪ D16」** 是 T3 最严的一道闸：三字名必须能被二字证据（自己的尾两字是真实二字名）
  或 D16 实证覆盖，否则不予放行。这一条把「三字姓名」的生造率压到最低。
- **⑥ 双语料校验**对应 issue 约束④「入库前须过 102 通用语料 + 1200 真实业务语料双零误伤校验」。

### 词表与既有各表的交集（实测）

| 表 | 与 `common_name_dict` 交集 |
|---|---|
| D16 `full_name_list` | **0** |
| `common_word_guards`（330 条） | **0** |
| `standalone_exempt_words`（`叶子`） | **∅** |
| `biz_guard_words` | **∅** |
| `placeholder_names`（8 条） | **∅** |

**D16 交集为 0 是本层的结构性优势**：本层只补 D16 没覆盖的姓名，不与 D16 争抢同一字符串，
故本层命中即整体脱敏，**无「张三丰被 2 字名层截断」的同类风险**（这正是 #56 的教训）。

## 三、匹配语义（工程约束②③ 的落地）

### 3.1 候选扫描：窗口扫描 + 右边界非汉字 + 姓氏位防截断

实现于 `_find_common_name_dict_candidates()`（`scripts/common_rules.py`）：

| 规则 | 判据 | 目的 |
|---|---|---|
| **长度互斥** | 同位置先试 3 字、再试 2 字，命中即止 | 3 字名不被 2 字候选从后往前切开 |
| **左边界：ASCII 字母数字相邻 → 跳过** | `left.isascii() and left.isalnum()` | 避免编码拼接场景（`IDATA-张明`）误命中 |
| **左边界：左邻为姓氏字 → 放弃** | `left in SURNAME_SET` | **姓氏位防截断**：「艾成军」中的「成军」不单独命中，宁可漏脱也不输出「艾XXX」残缺姓名（与 #56「长名优先」同源） |
| **左边界：左邻+候选本身是更长词典条目 → 让位** | `(left + cand) in words` | 更长分支优先 |
| **右边界：紧邻汉字 → 放弃** | **issue 约束③「要求右边界非汉字」** | 避免「王明生」类串词误命中 |
| **游标推进** | 命中跳整段，未命中前进一格 | 避免与内部子串重复命中（初版未推进导致死循环，已修） |

### 3.2 语义方案对照（实测 1200 语料新增命中数）

| 语义方案 | 102 新增 | 1200 新增 | 裁决 |
|---|---|---|---|
| 整词语义 / 严格（候选须为完整汉字连续段，左右均非汉字） | 0 | 0 | 召回不足（仅姓名孤立成段时命中） |
| **宽松窗口扫描 + 既有守卫链** | **0** | **0**（原始 2 → 守卫后 0） | ✅ **采纳** |
| 子串级零出现过滤（剔除 30 条） | 0 | 0 | 属**语料特异裁剪**，否决 |

> **重要结论：无需语料特异裁剪。** 原始词典在宽松语义下会在 1200 语料产生 2 条新增命中
> （`关方`、`向真`），但二者均被**既有守卫链**拦截：
> - `关方` → `common_word` / `biz_word` / `common_word_guard` / `boundary_split` **四重拦截**
> - `向真` → `boundary_split` 拦截
>
> 即「宽松匹配 + 既有守卫」自然收敛到 0，无需为本次语料定制词表裁剪——
> 这满足 #49 的核心教训：**判据本身要站得住，不能靠词表兜底**。

### 3.3 守卫链复用

`_apply_common_name_dict_pass()` 复用既有全套守卫：

- 银行链锁定（`宁波银行`/`甘肃银行` → `XX银行`）
- Agent skip
- 幂等占位符保护（`XXX` 不二次处理）
- **G4 整词保护**（`common_word_guards`）
- G7 跨词边界
- 常用词覆盖
- 独立成词豁免（`standalone_exempt_words`，真名优先语义）
- 业务词守卫（`biz_guard_words`）

计数标签：`counts["姓名"]`。

## 四、性能：哈希查表 + 逐位扫描（不编译 alternation 正则）

| 方案 | 实测 |
|---|---|
| 117201 条 alternation 编译成单条正则 | **6.91s**（不可接受） |
| 哈希查表 + 逐位扫描（1200 语料） | **< 0.05s** |

### G4 整词守卫的必要条件剪枝

首版实现总耗时 **2.12s**，其中 G4 整词守卫独占 **873ms（41%）**——800 个候选逐个跑整词保护检查。

**剪枝原理**：G4 豁免的前提是「命中片段是某个保护词的子串」。
因此先取整词保护表中长度 2/3 的**全部子串集合**（`_get_common_word_guard_substrings()`，带缓存），
命中片段若**不在**该子串集合中，则**必然**不满足 G4 豁免条件 → 直接早退 `False`。

```python
if len(matched) in (2, 3) and matched not in _get_common_word_guard_substrings():
    return False
```

**等价性验证**：14.7 万个区间逐一与「未剪枝参考实现」比对，**零差异**，语义完全等价。
该剪枝同时优化了既有通道（G4 被姓名规则组、地址通道等共用），总耗时 **2.12s → 1.20s**，
**低于词典层上线前的 1.58s 基线**——即本层对整体性能是**负开销**。

## 六、代码落点

### `scripts/common_rules.py`

| 符号 | 作用 |
|---|---|
| `_COMMON_NAME_DICT` / `_COMMON_NAME_DICT_LENS` | 词典缓存与候选长度（3, 2） |
| `_get_common_name_dict()` | 词表加载器（`common_name_dict_enabled` / `common_name_dict_file`；多路径候选解析；仅收 2/3 字全汉字） |
| `_find_common_name_dict_candidates()` | 候选扫描器（§3.1 全部规则） |
| `_apply_common_name_dict_pass()` | 脱敏通道（逆序替换 + 既有守卫链；计数标签「姓名」） |
| `_get_common_word_guard_substrings()` | G4 必要条件剪枝用子串集（带缓存） |
| `_is_protected_by_common_word_guard()` | 早退剪枝点 |
| `apply_redactions_counted()` | **主链路接入点**：在 `_apply_nc_region_name_pass()` 之后、**姓名规则组之前**执行 |
| `reset_patterns()` | 新增两个缓存的清理（`_COMMON_NAME_DICT` / `_COMMON_WORD_GUARD_SUBSTRINGS`） |

> **主链路顺序是关键**：词典层必须在姓名规则组**之前**，否则 D16 2 字名层会先吃掉三字名的前两字
> （#56 的同类问题）。且本层在 N-C 区域层之后，使「区域名单段」优先由更强的区域证据处理。
