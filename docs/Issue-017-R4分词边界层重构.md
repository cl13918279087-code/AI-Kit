## 概述

v1.3.10 完成了 N-A（表格角色列检测）和 N-B（段落锚点扩散），是现有枚举体系的补丁式增强。当前 `surname_pool`（201字）+ `name_pool`（152字）两段枚举架构存在根本局限：name_pool 永远滞后，无法穷举所有真实姓名第二字。

R4 的目标是**架构级重构**：用「分词边界层 + 上下文评分」替代枚举式检测，实现姓名覆盖率 ≥ 96%（标准版基准），同时误伤率 ≤ +5%。

## 问题量化

| 来源 | 姓名总数 |
|------|---------|
| 标准版（benchmark） | 1249 |
| v1.3.9 | 739 |
| v1.3.10（N-A+N-B） | 待测，预计 ≥ 1000 |
| **R4 目标** | **≥ 1200（96%）** |

## R4 核心设计方向

### 1. 分词边界层（替代枚举池）

**当前问题：** surname_pool + name_pool 两段枚举，name_pool 第二字永远滞后。

**改进思路：** 不依赖枚举池，用中文分词工具做词边界识别，再结合角色上下文判断是否为姓名。

```
文本 → 分词 → 词边界识别 → 上下文评分 → 是否为姓名
```

**关键技术选型（待评审）：**
- `jieba`（轻量、离线可用、无外部依赖）
- `hanlp`（更准确、需下载模型或网络 API）
- 自研基于 CRF/HMM 的轻量边界识别器

### 2. 上下文评分

**当前问题：** 角色词锚点依赖手工枚举，扩展成本高。

**改进思路：** 根据上下文特征打分，多特征综合判断"这是人名"：

| 特征 | 说明 | 权重 |
|------|------|------|
| 姓氏池命中 | 2字块首字在姓氏池 | 高 |
| 名字常见度 | 第2-4字在常用名字库 | 中 |
| 周围角色词 | 前后有组长/成员/负责人等 | 高 |
| 密度信号 | 同区域出现多个类似词块 | 高 |
| 停用词冲突 | 与常用词（提高/业务等）重叠 | 低 |
| 数字比例 | 附近数字比例 > 40% | 低 |

综合评分 ≥ 阈值 → 脱敏

### 3. 与现有 N-A/N-B 的关系

| 模块 | R4 处理方式 |
|------|-----------|
| N-A 表格角色列 | 作为高置信通道**保留**，R4 覆盖不到时兜底 |
| N-B 段落锚点扩散 | R4 中作为**特征输入**（角色词权重加分） |
| surname_pool | R4 中降级为特征权重，不作为硬匹配 |
| name_pool | R4 中降级为名字常见度评分特征 |

---

## 与现有规则的关系

```
Layer 0: name_pool 枚举（保留作为特征，不作硬匹配）
Layer 1: 区域预判 × 批量脱敏（保留，N-A/N-B）
Layer 2: surname_pool 区域扩散（N-D，待 R4 评估）
Layer 3: LLM（现有，不变）
Layer R4: 分词边界 + 上下文评分（新增，叠加）
```

## 讨论事项（请评审确认）

1. **技术选型**：jieba（轻量离线）vs hanlp（更准需模型）？
2. **与 N-A/N-B 的衔接**：R4 替代后 N-A/N-B 是保留、合并还是废弃？
3. **配置化粒度**：`--name-mode=r4|enum|both` 是否需要？
4. **误伤防护**：R4 评分阈值如何标定？低分区域是否回退到 LLM 兜底？
5. **N-D 处置**：surname_pool 区域扩散（N-D）是否作为 R4 Phase 2 的一部分？
6. **时间线**：预计 R4 在哪个版本号发布？
