## 二、逐条实测复现结果

### 改进 1/2：姓名规则（指控属实，P0）⭐

清单样例全部复现，另发现新误伤面：

| 输入 | 当前输出 | 判定 |
|---|---|---|
| 说明书 | 说XXX | 误伤 ✅复现 |
| 交易进度 | 交XXX度 | 误伤 ✅复现 |
| 实施方案 | 实XXX案 | 误伤 ✅复现 |
| 测试阶段范围 | 测试阶XXX围 | 误伤 ✅复现 |
| 每周三 | 每XXX | 误伤 ✅复现 |
| 方向明确 | XXX确 | 误伤（新发现） |
| 张锋 | XXX | **已命中**（"锋"已入字符表，清单改进2部分过时） |
| 张三;李四 | XXX;**李四** | 漏检（新发现：分号左侧二字名漏） |

**评估**：清单称"误伤率 90%"基于晋商银行单文档 58 命中 6 真实，方向可信。结构性根因成立：闭集"姓氏字+名字字符表"无法区分"高频普通词"与"人名"，加黑名单是打地鼠，不可持续。**同意"必须回传"**。

**整改方向**（需评审决策，不建议直接照搬 v2 方案）：
- v2 的"上下文触发白名单"方案会把大量无角色词上下文的真实人名漏掉（如"由张锋负责"虽覆盖，但正文叙述"张锋确认了方案"会漏）——**漏脱敏是合规事故，误伤只是可用性问题，二者风险不对称**
- 建议折中方案：保留字符表正则作为候选生成器 + 增加**中文分词边界校验**（jieba：若候选命中连续词典词如"说明书/实施方案/每周"则剔除）+ 扩充上下文触发通道覆盖剩余场景 + 保留 LLM Agent 检测通道兜底（上游已具备）
- 压缩误伤的具体快速补丁：`_NO_NAME_WORDS` 扩充清单实测的 52 词（可作为 P0 热修先行合入，结构重构作为 P1）

### 改进 3：日期占位（指控属实，且比清单更严重，P0）

| 输入 | 当前输出 | 判定 |
|---|---|---|
| 2020年5月发布 | YYYY/MM/DD月发布 | 占位符错乱+残字 ✅复现 |
| **2020-4-26上线** | **2020-4-26上线** | **完全未脱敏（漏脱敏！）** |
| **2020/5/1实施** | **2020/5/1实施** | **完全未脱敏（漏脱敏！）** |
| 2026年9月1日 | YYYY年MM月DD日 | 正常 |

**评估**：清单只指出占位符美观问题（YYYY/MM/DD月），实测发现**更严重的合规问题——单位数月/日的短日期完全漏脱敏**（现有正则要求两位月/日）。这是漏脱敏风险，优先级高于占位对齐。同意回传，但整改范围应扩大。

### 改进 4：图片 OCR 选区脱敏（指控属实，P1）

上游 `_redact_bank_logos` 仅按文件名/宽高比猜测 logo 全图遮黑，无 OCR 能力。组织架构图 40+ 人名泄露场景成立。同意回传，RapidOCR 作可选依赖 + 无环境时降级为"图片标记人工检查"的方案合理。

### 改进 5：页眉/页脚引用图片确定性遮盖（指控属实，P1）

上游无 header/footer `.rels` 反查逻辑，非 logo 比例的页眉图片会走"无命中→保留"分支泄露。同意回传，确定性路径（引用即遮盖）设计正确。

### 改进 6：段落级文本合并（**已过时，无需整改**）

清单称"单节点跑正则会漏匹配"。实测当前上游 `_extract_full_text`（redact_word.py L155-182）**已按 `<w:p>` 段落跨 run 拼接全部 w:t**，`apply_redactions` 在拼接全文上执行，`_apply_spans_to_nodes`（L223+）用 bisect 按字符区间精确回写各节点，明确注释"支持实体跨多个 run 拆分"。这正是清单要求的能力，且上游 v3 的精确区间切片比 v2 的"按长度比例回写"更准。**该条与现状重复，不采纳**（清单编制时可能基于旧版本 diff）。

### 改进 7：静默失败治理（指控属实，P1）

`_redact_bank_logos` L482 图片处理失败仅 `print("[警告]...")` 继续流程。WinError 5 场景成立。同意回传，"人工检查项清单 + 计数汇报"成本低收益高。

### 改进 8：docProps 深度清理（指控属实，根因在规则顺序，P1）

`core.xml` 上游已接入 `apply_redactions`，但实测：

| 输入 | 当前输出 | 判定 |
|---|---|---|
| 宁夏银行核心系统 | **宁XXX行**核心系统 | 银行名被姓名规则截胡 ✅复现 |

根因不在"缺处理"，而在**银行名规则未命中"宁夏银行"**（现规则面向已知银行白名单），"宁夏银"反被姓名正则匹配。整改：银行名规则改为通用模式（`[\u4e00-\u9fa5]{2,6}银行`）优先于姓名规则执行，docProps 问题随之消解。同意回传。
