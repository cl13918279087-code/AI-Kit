## 一、项目背景与目标

### 1.1 项目背景

在银行 IT 项目实施过程中，项目文档（含项目规划、测试报告、会议纪要、需求说明书等）不可避免地涉及银行内部人员姓名、银行业务系统名称、项目里程碑日期等敏感信息。这类文档在对外交付、存档或分享前，必须完成脱敏处理，以满足金融行业数据安全合规要求。

传统脱敏方式依赖人工逐字审阅，存在效率低、易遗漏、尺度不一等问题。本项目旨在建设一套半自动化的文档脱敏能力，集成到 WorkBuddy AI 助手平台，支持常见的 Word、PPT、Excel、PDF、图片五类文档格式，实现常见敏感信息的自动识别与标准化替换。

### 1.2 项目目标

1. **覆盖主流文档格式**：Word（.doc / .docx）、PPT（.ppt / .pptx）、Excel（.xls / .xlsx）、PDF、图片（.png / .jpg / .jpeg / .bmp）
2. **自动识别并替换多类敏感信息**：人员姓名、银行名称、日期、身份证号、手机号、固话、邮箱、详细地址、银行卡号、银行 Logo
3. **保留原始文档格式**：脱敏操作不破坏标题层级、目录结构、表格、页眉页脚、嵌入图片等原有格式
4. **统一脱敏常量**：所有敏感信息按统一规则替换，不可逆，不可还原

## 四、处理流程要求

### 4.1 通用处理流程

所有格式统一遵循以下处理顺序（链式替换，防止短文本误伤）：

```
第一阶段（前置规则）：电子邮箱 → 身份证号 → 银行卡号 → 日期信息 → 手机/固话 → 银行名称/Logo → 地名库精确匹配
第二阶段（回溯式地址通道）：_apply_address_pass()，处理省/市/县/区/街道/路/楼盘/大厦/支行/分行/门牌号
第三阶段（姓名规则）：预设名单 → 角色词推断 → Rule A/B/C
第四阶段（后处理纠错）：修正已知误脱敏（如"清单如下"、"营运计财部"）
```

**执行原则：**
- 先处理长文本/高精度规则（电子邮箱、身份证号），后处理短文本规则（姓名、手机号）
- 同一位置不重复替换
- 替换操作从后往前执行，防止索引偏移导致替换错位
- **地址通道必须在姓名规则之前执行**，防止"金水""花园"等地址成分被姓名规则误吞

### 4.1.1 回溯式地址脱敏通道（_apply_address_pass）

地址识别不依赖预置地名库，采用**从后缀向左回溯收集地名前缀**的策略，可处理完整地址链：

- **匹配对象**：`街道 / 大道 / 大街 / 写字楼 / 楼盘 / 小区 / 公寓 / 广场 / 大厦 / 大楼 / 省 / 市 / 县 / 区 / 镇 / 乡 / 村 / 街 / 路 / 巷 / 弄 / 支行 / 分行 / 号` 共 24 类后缀
- **回溯机制**：从后缀起点向左收集最多 5 个连续汉字作为地名前缀，遇边界字符即停止
- **跨后缀处理**：`支行` / `分行` 允许跨越一个行政后缀（如"中牟县支行" → `XX县支行`，保留"县"）
- **边界保护**（停用词集，遇之停止回溯）：
  - 虚词/动词：的了在是和与或及到从去进被把将已会能可要等
  - 行政边界字：省市县区镇乡村街路巷弄（防跨行政区吞并）
  - 高频易误伤词：其中、银行、位于、面临等
- **误伤防护**：
  - 指示词场景不替换（如"这栋大楼""该大厦"）
  - 前缀不足 2 字不替换（如"城市化""超市"）
  - 后缀+下一字组合守卫（如"市场部""区别""县长""省委"）
  - 已替换的 XX 占位符不二次替换（避免 `XX县XX县支行`）

### 4.2 Word 文档处理要求

1. **格式保留**：标题/目录/表格/页眉页脚/图片 全量保留，不因脱敏操作丢失
2. **文本来源全覆盖**：段落文本、表格单元格、文本框（txbx）、页眉页脚、批注作者/内容
3. **姓名发现机制**（三规则体系）：
   - 预设人员名单精确匹配（已知姓名库）
   - 角色词上下文智能推断（如"系统负责人：[姓名]"模式）
   - Rule A：常见姓氏 + 高频名字用字（通用场景，前后非 ASCII/数字）
   - Rule B：冒号后2字姓名（如"总行支持人员：汪晶晶"）
   - Rule C：冒号后姓氏+单字名（如"组长：樊霖副组长"，处理角色词后紧跟2字姓名但第2字是单名）
4. **换行处理**：Word 内部字段代码（TOC、HYPERLINK、PAGEREF、TIME 等）在脱敏前清洗，防止干扰正则匹配

### 4.3 PPT 演示文稿处理要求

1. **处理范围**：幻灯片正文、表格、形状内文本、组合图形文字、演讲者备注、页眉页脚
2. **格式保留**：母版布局、动画设置、切换效果不变
3. **备注页**：与正文同等脱敏处理，不遗漏

### 4.4 Excel 电子表格处理要求

1. **处理范围**：单元格文本/数值/日期、批注、页眉页脚
2. **公式处理**：公式计算结果中的敏感值被替换；公式逻辑本身不修改
3. **单元格类型**：日期格式统一转为文本后再写入，防止格式回写

### 4.5 PDF 文档处理要求

1. **文本型 PDF**：提取文本坐标，用黑色矩形遮盖原区域并写入占位符
2. **扫描版 PDF（纯图片）**：调用图片脱敏流程（OCR + 图像遮盖）
3. **遮盖精度**：覆盖文字 Bounding Box 四周边缘 2-3px，防止边缘残留

### 4.6 图片处理要求

1. **处理流程**：OCR 定位文字 → 正则识别敏感信息 → 物理坐标区域黑色遮盖或马赛克
2. **默认方式**：马赛克像素化，彻底消除文字可辨认性
3. **适用场景**：PDF 内嵌截图、扫描件、拍照文档

## 五、质量标准

### 5.1 准确性要求

| 敏感类型 | 准确率要求 | 误脱敏容忍度 |
|---|---|---|
| 电子邮箱 | ≥ 99% | 极低（邮箱格式明确，误判少） |
| 身份证号 | ≥ 99% | 极低（18位格式明确） |
| 银行卡号 | ≥ 95% | 低（16-19位数字可能与其他编号混淆） |
| 手机号 | ≥ 98% | 低 |
| 日期 | ≥ 95% | 中（多种书写格式） |
| 银行名称 | ≥ 98% | 低 |
| 人员姓名 | ≥ 90% | 中（2字姓名与普通词语可能混淆） |
| 地址 | ≥ 90% | 中（地址模式复杂） |

### 5.2 格式保留要求

- 脱敏后文档与原始文档的标题样式、目录结构、表格行列完全一致
- 页眉页脚内容、页码位置不变
- 嵌入图片的位置和尺寸不变
- 不产生额外的空白段落或多余的空行

### 5.3 完整性要求

- 脱敏后的文件可直接打开使用，不出现文件损坏、格式错乱
- 文档总字数与原始文档误差不超过 5%（由替换常量长度差异造成）
