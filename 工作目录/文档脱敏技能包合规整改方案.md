## 二、P0 问题修复详情

### P0.1 API Key 占位符导致 Mock 模式失效

**问题**：config.json 中 api_key 设为 `"***"` 时，`not bool("***") = False`，走了真实 API 路径但 key 无效，导致全部 LLM 调用静默失败。

**根因**：`llm_client.py` 第 135 行：
```python
# 旧代码
self.mock_mode = not bool(self.api_key)  # "***" → False → 走真实请求
```

**修复**（`llm_client.py`）：
```python
# 排除常见占位符："***"、"your-key-here"、空字符串
_placeholder_keys = {"***", "your-key-here", "your_api_key", "sk-placeholder", ""}
self.mock_mode = (
    not bool(self.api_key)
    or self.api_key.strip() in _placeholder_keys
)
```

**验证**：重启 pipeline，若 api_key 为占位符，日志输出：
```
⚠️ 未配置 API Key，自动启用 DEMO_MOCK 模式
```

### P0.2 editor_sdk file_id 返回值误用

**问题**：`open_file()` 返回输入的 `file_path` 而非 SDK 分配的真正 file_id，后续 `get_document_content` / `execute_manifest` 传入错误的 file_id。

**根因**：`editor_executor.py` 第 130 行：
```python
return file_path  # ❌ 错误：返回路径而非 SDK 分配的 ID
```

**修复**（`editor_executor.py`）：
```python
def open_file(self, file_path: str) -> str:
    result = self._run("open_file", file_path=file_path)
    if "error" in result:
        raise RuntimeError(f"打开文件失败: {result['error']}")

    # 尝试从响应中提取真实的 file_id（字段可能是 file_id / id / data.file_id）
    file_id = result.get("file_id") or result.get("id") or result.get("data", {}).get("file_id")
    if not file_id:
        logger.warning(
            f"⚠️ editor_sdk 响应中未找到 file_id 字段，"
            f"降级使用 file_path 作为 file_id"
        )
        file_id = file_path
    return file_id
```

### P0.3 subprocess shell=True 命令注入风险

**问题**：`editor_executor.py` 第 67 行，`sdk_path` / `file_path` 未做转义直接拼入 shell 命令，存在命令注入风险。

**修复**（`editor_executor.py`）：改用 `shlex.split` + `shell=False`：
```python
import shlex

def _run(self, subcmd: str, **params) -> dict:
    base_parts = shlex.split(self.sdk_cmd)
    cmd_parts = base_parts + ["call", subcmd]
    for k, v in params.items():
        if isinstance(v, str):
            cmd_parts.append(f"{k}={shlex.quote(v)}")  # 安全引用
        elif isinstance(v, bool):
            cmd_parts.append(f"{k}={'true' if v else 'false'}")
        elif isinstance(v, (int, float)):
            cmd_parts.append(f"{k}={v}")
        else:
            cmd_parts.append(f"{k}={shlex.quote(str(v))}")

    proc = subprocess.Popen(
        cmd_parts,  # shell=False
        stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True,
    )
```

## 三、P1 问题修复详情

### P1.1 脱敏审计留痕机制

**问题**：manifest 无操作者身份、无精确时间戳、无文档哈希，无法满足金融监管留痕要求。

**修复**（`manifest.py`）：新增两个类：

```python
@dataclass
class RedactionAuditRecord:
    """脱敏操作审计留痕记录"""
    operator_id: str           # 操作者工号
    operator_name: str        # 操作者姓名
    operation_time: str       # ISO 8601，含时区
    document_name: str        # 原文档名称
    document_hash_original: str  # 原文档 SHA-256
    document_hash_redacted: str  # 脱敏后 SHA-256
    tool_version: str         # 工具版本
    llm_model: str            # LLM 模型
    total_replacements: int   # 总替换次数
    approved_entities: list   # 人工确认的实体
    rejected_entities: list  # 人工拒绝的实体
    low_confidence_reviewed: int  # 低置信复查数
    execution_duration_seconds: float

class AuditLog:
    """审计日志管理器"""
    def new_record(self, document_name: str, llm_model: str) -> RedactionAuditRecord
    @staticmethod
    def compute_file_hash(file_path: str) -> str  # SHA-256
    @staticmethod
    def get_operator_from_env() -> tuple[str, str]  # 支持 LDAP/SSO 扩展
```

**使用方式**：
```python
from manifest import AuditLog

log = AuditLog(*AuditLog.get_operator_from_env(), tool_version="1.1.0")
record = log.new_record("XX银行文档.docx", llm_model="MiniMax-Text-01")
# ... 执行脱敏 ...
record.document_hash_original = log.compute_file_hash(input_path)
record.document_hash_redacted = log.compute_file_hash(output_path)
record.total_replacements = len(exec_result["succeeded"])
record.save_json(output_path.rsplit(".", 1)[0] + "_audit.json")
```

### P1.2 账号正则过度匹配

**问题**：`ACCOUNT_PATTERN = \b(\d{10,20})\b` 匹配任意长数字，误伤流水号、页码、产品代码。

**修复**（`entity_detector.py`）：改为上下文感知 + 标准格式验证：
```python
# 旧版（已废弃）
ACCOUNT_PATTERN = re.compile(r'\b(\d{10,20})\b')

# 新版：要求明确上下文标识 + 银行标准账号格式（16-19位）
ACCOUNT_CONTEXTUAL_MARKERS = ["账号", "账户", "卡号", "账号为", "账户为", "卡号为"]
ACCOUNT_STANDARD_PATTERN = re.compile(
    r'(?:' + '|'.join(re.escape(m) for m in ACCOUNT_CONTEXTUAL_MARKERS) + r')'
    r'\s*'
    r'(\d{16,19})'  # 银行标准账号：行号+币种+类型+序号 = 16-19位
)
# 兜底：纯 16-19 位数字（大概率账号，但标注低置信）
ACCOUNT_FALLBACK = re.compile(r'\b\d{16,19}\b')
```

### P1.3 日期语义感知

**问题**：`2022年4月8日至2022年4月10日` → `YYYY年MM月DD日至YYYY年MM月DD日`，丢失了"3天周期"语义。

**修复**（`entity_detector.py`）：新增日期范围检测和语义保留策略：

| 类型 | 原文示例 | 替换结果 | 策略 |
|------|---------|---------|------|
| 时间点 | 2022年4月8日 | YYYY年MM月DD日 | 直接替换 ✅ |
| 日期范围 | 2022/04/08至2022/04/10 | YYYY/MM/DD至YYYY/MM/DD | 保留连接符 ✅ |
| 时间序列 | 第1次演练、第2次演练 | 保留"第N次"词本身 | 不替换顺序词 ✅ |

```python
# 新增 _regex_detect_date_ranges 方法
DATE_RANGE_PATTERNS = [
    # 中文日期范围：两端日期统一替换，连接符（至/——）原样保留
    (re.compile(
        rf'({_YEAR4_CN}年{_MONTH_PAT}{_DAY_PAT}日)'
        r'(至|——|[-~])'
        rf'({_YEAR4_CN}年{_MONTH_PAT}{_DAY_PAT}日)'
    ), "date_range"),
    # 时间序列：第N次/第N轮/第N阶段 — 保留词本身，不替换
    (re.compile(r'(?:第\s*[一二三四五六七八九十百0-9]+\s*次|'
                r'第\s*[一二三四五六七八九十百0-9]+\s*轮)'),
     "time_sequence"),
]
```

### P1.4 "海峡"排除词细化

**问题**：`"海峡"` 在 `EXCLUDED_COMMON_WORDS` 中全局排除，导致"海峡银行"被漏脱敏。

**修复**（`entity_detector.py`）：
1. 从 `EXCLUDED_COMMON_WORDS` 移除孤立的 `"海峡"`
2. 新增 `_is_geographic_haixia()` 上下文感知函数
3. 在最终过滤时，对 `"海峡"` 进行上下文判断

```python
def _is_geographic_haixia(text: str, context: str = "") -> bool:
    """判断'海峡'是否为地理含义"""
    geo_suffixes = {"台湾", "两岸", "地区", "水域"}
    bank_suffixes = {"银行", "金融", "股份"}

    if text.strip() in {"台湾海峡", "海峡两岸", "海峡地区"}:
        return True  # 地理，排除 ✅
    if "银行" in context or "金融" in context:
        return False  # 银行名，不排除 ❌
    if text.strip() == "海峡":
        return True  # 单独海峡，默认地理
    return False
```

### P1.6 Phase 5 验证逻辑修正

- `dry_run=False` 时，若 editor_sdk 未落盘，`get_document_content` 读到原文本，验证假阳性通过

if dry_run:
    verification = {
        "checks": {"bank_names_check": "DRY_RUN", ...},
        "quality_score": -1,

        "dry_run_note": "实际质量验证需在非 dry_run 模式下执行",
